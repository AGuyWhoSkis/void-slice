# M6 — Preview environments

Today every commit lands in `main` and ships straight to production via the Worker + Pages deploy. That worked while this was a single-author project; it doesn't survive the addition of collaborators. M6 inverts the pipeline: commits go to PR branches, each PR gets a full-stack preview deployment (matched Worker + Pages, both pinned to that PR's commit), `main` becomes protected, and merging to `main` is the only event that updates production. Success looks like: a PR opens, CI builds and deploys a preview, reviewers click a URL to exercise the change end-to-end, and `main` is no longer push-able. With that in place, the PR pipeline is ready for collaborators — the collaboration spec itself follows separately.

**Scope:** `wrangler.toml` (parametric `[env.preview]` alongside `[env.production]`), `.github/workflows/ci.yml` (deploy job triggers on PR events, computes a deterministic preview Worker URL from the PR/branch, passes it into the Pages build as a per-run `VITE_API_URL` override), `web/` build wiring to honor that override, and GitHub branch-protection settings on `main`. The design treats "deployment environment" as a first-class concept so adding a `staging` env or a third deployable artifact later is a config row, not a rewrite. Excludes the collaboration spec (separate, deliberately blocked on M6 completing), and excludes the deferred items already named in `cloudflare.md` § 3 — diagnostic-count cap, post-deploy smoke, automated rollback, `_headers`, cache layer, `compatibility_date` discipline. `cloudflare.md` itself is superseded by this goal; the final M6 ticket consolidates its content into a future Deployment goal and removes the file. Idle preview Workers cost $0 incrementally on the existing $5/mo Workers Paid plan, so previews are left up rather than torn down on PR close.

**Status:** active.
