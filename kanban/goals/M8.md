# M8 — Playground bisection ladder

The playground stack — Go linter → wasm export → Cloudflare Worker → frontend — is well-tested at the bottom (`go test ./...`) and at the top ([M6](M6.md) preview deploys), but opaque in the middle. When an end-to-end behavior is wrong, there's no way to localize the failure to a layer without a redeploy cycle. M8 closes that gap by giving each middle layer an isolated harness, plus a differential oracle that diffs outputs across layers when something disagrees. The unit of value is **diagnostic speed**: a future playground bug should be bisectable to a single layer in seconds, not minutes-per-redeploy.

**Scope:** the wasm boundary, the Worker glue ([worker/index.js](../../worker/index.js)), and the frontend transport ([web/src/api.ts](../../web/src/api.ts)). The differential oracle composes the per-layer harnesses and depends on them. Excludes UI/component tests in the frontend (deliberately, to stay durable across UI churn), specific playground bugs (separate tickets, scoped to whichever goal owns playground behavior), and any redeploy-pipeline work ([M6](M6.md), [M7](M7.md)).

**Status:** done.
