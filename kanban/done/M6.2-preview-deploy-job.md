# M6.2 · Workflow trigger split + preview-deploy job

**Status:** done
**Goal:** M6
**Size:** small-to-medium
**Blocks:** M6.3, M6.4

## What

Eliminate CI double-runs (PR + push fire today on the same commits) and add the `preview-deploy` job: per-PR Worker version + per-branch Pages deploy, with both URLs surfaced as a sticky PR comment.

Each PR gets:
- A non-production Worker version on the `voidslice-api` script, aliased `pr-<N>`, reachable at `https://pr-<N>-voidslice-api.<acct>.workers.dev`.
- A Pages preview at `https://pr-<N>.voidslice.pages.dev`, built with `VITE_API_URL` pointing at the alias Worker URL.

## Scope

[.github/workflows/ci.yml](../../.github/workflows/ci.yml):

**Triggers** — replace `push: branches: ["**"]` + `pull_request: branches: [main]` with:
```yaml
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
```
Feature-branch pushes that aren't part of a PR get no CI — intentional; the PR is the unit of work.

**New `preview-deploy` job:**
- `if: github.event_name == 'pull_request' && github.event.pull_request.head.repo.full_name == github.repository` (same-repo PRs only — fork PRs auto-skip; secrets aren't exposed to forks).
- `needs: [test, lint, build]`.
- Build Worker WASM (`./worker/build.sh`).
- `wrangler versions upload --preview-alias pr-${{ github.event.number }}` via `cloudflare/wrangler-action@v3`. **Verify the exact flag with `npx wrangler versions upload --help` against the pinned Wrangler version before merging** — older versions used plain `--alias`.
- Capture the alias URL by parsing `wrangler` stdout (don't template it from a constant — the account subdomain isn't reliably known in CI). Expose as a job output.
- `npm ci && npm run build` in `web/` with `VITE_API_URL=<that URL>`.
- `wrangler pages deploy web/dist --project-name=voidslice --branch=pr-${{ github.event.number }}`.
- Post both URLs as a sticky PR comment using `marocchino/sticky-pull-request-comment@v2`.

**Rename `deploy` → `production-deploy`:**
- `if: github.event_name == 'push' && github.ref == 'refs/heads/main'`.
- Body unchanged from M6.1.

## Notes / landmines

- **Pages `--branch=<name>` URL minting.** Training-era behavior is "any string mints `<branch>.<project>.pages.dev`", but some accounts have tightened this. If `pr-<N>.voidslice.pages.dev` doesn't materialize on the first PR, fall back to the auto-assigned per-deploy URL emitted by `wrangler pages deploy`.
- **Skipped jobs and required checks.** `preview-deploy` will be marked as a required check in M6.4. Skipped jobs are *not* "passed" in branch-protection semantics — fork PRs would be blocked from merging the moment the rule lands. M6 supports same-repo only, so this is moot today; documented in M6.4.

## Dependencies

M6.1 (wrangler.toml restructure must land first; this job assumes the single-script model).

## Verification

- Open a PR. CI runs once (no double-trigger from PR + push).
- `preview-deploy` job completes; comment appears on the PR with two URLs.
- `curl https://pr-<N>-voidslice-api.<acct>.workers.dev/health` → 200.
- Pages preview loads; dragging `testdata/broken/count-mismatch.decl` produces `VALIDATE_ARRAY_COUNT_MISMATCH`. Network tab confirms `/lint` hits the alias Worker, not localhost or prod.
- After merge to `main`, `production-deploy` runs and prod is updated.
- `go test ./...` and `go vet ./...` pass.

## Completion

**What was done**

- [.github/workflows/ci.yml](../../.github/workflows/ci.yml):
  - Triggers narrowed: dropped the `push: branches: ["**"]` glob; only `pull_request: [main]` and `push: [main]` fire CI now. Feature-branch pushes that aren't part of a PR get no CI.
  - New `preview-deploy` job (same-repo PRs only): builds the Worker WASM, runs `wrangler versions upload --preview-alias pr-<N>`, captures the alias URL from stdout, builds the SPA with `VITE_API_URL` set to that URL, deploys Pages with `--branch=pr-<N>`, posts a sticky PR comment with both URLs via `marocchino/sticky-pull-request-comment@v2`.
  - Renamed `deploy` → `production-deploy`; gating unchanged (`event_name == 'push' && ref == 'refs/heads/main'`).

**Decisions**

- **Bypassed `cloudflare/wrangler-action@v3` for the steps that need stdout.** The action's `command-output` came back empty in practice, so URL extraction failed. Running wrangler directly via `npx -y wrangler@4.86.0 …` lets the shell capture stdout naturally. The action wrapper is still fine for steps where output isn't consumed (production-deploy still uses it).
- **Pinned Wrangler 4.86.0 explicitly** on the preview-deploy steps. The action's default is 3.90.0, where `--preview-alias` does not exist (the flag was added in Wrangler 4.x). Production-deploy is intentionally left on the action's default — it's been working fine and bumping it is out of scope for M6.2.
- **Pages URL is templated, not parsed** from stdout. We own both inputs (`project=voidslice`, `branch=pr-<N>`), so `https://pr-<N>.voidslice.pages.dev` is deterministic. Less brittle than scraping wrangler output for a Pages URL.
- **Worker URL is parsed** from stdout via `sed -n 's/^Version Preview Alias URL: //p'`. The account subdomain (`voidslice`) isn't a constant we want to bake into CI as a magic string — taking it from wrangler's own output keeps the workflow account-agnostic.

**Verification**

- PR #1 opened; CI ran once (no PR/push double-trigger).
- `preview-deploy` succeeded; sticky comment appeared with both URLs.
- `curl https://pr-1-voidslice-api.voidslice.workers.dev/health` → `{"status":"ok"}`.
- Pages preview at `https://pr-1.voidslice.pages.dev` loaded; sample-button-driven `count-mismatch.decl` produced the expected `VALIDATE_ARRAY_COUNT_MISMATCH` diagnostic — confirming `VITE_API_URL` was correctly baked into the SPA build pointing at the alias Worker.
- Pre-existing paste-flow bug observed during verification (file-paste path doesn't surface diagnostics on the deployed playground); not a regression introduced by M6.2 and out of scope here.

**Landmines hit during implementation**

1. **Wrangler version mismatch** (`--preview-alias` not on action default 3.90.0). Fixed by pinning 4.86.0.
2. **`command-output` empty from wrangler-action.** Fixed by running wrangler directly via npx.
3. **Worker root path returns 404 by design** ([worker/index.js:161-169](../../worker/index.js#L161-L169) only routes `/health` and `/lint`). Initial smoke test against bare URL was misleading; verify via `/health` instead.
