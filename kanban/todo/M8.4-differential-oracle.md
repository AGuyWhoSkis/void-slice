# M8.4 · Differential oracle

**Status:** todo
**Goal:** M8
**Size:** medium
**Blocks:** nothing (final M8 ticket)

## What

Compose the three layer harnesses (M8.1, M8.2, M8.3) plus the native Go path (`internal/lint`) into a single command that runs the same input through all four and asserts the outputs agree. When they disagree, the oracle names the boundary where divergence first appears — that's the bisection. This is the unit of value M8 promises: "a future playground bug should be bisectable to a single layer in seconds, not minutes-per-redeploy."

## Scope

What must end up true:

- A single command — `make` target or equivalent — runs the oracle. No flags required for the default run.
- For each input in a shared corpus, the oracle obtains the lint result via four paths:
  1. Native Go (`internal/lint` directly).
  2. WASM-boundary harness (M8.1).
  3. Worker-local harness (M8.2).
  4. Frontend-transport harness (M8.3), pointed at the local Worker from path 3.
- The oracle compares the four outputs and reports either "all agree on N inputs" or "diverged at input X: native vs wasm match; worker disagrees on field Y" — naming the first boundary where the chain breaks.
- The corpus is the union of fixtures used by M8.1–M8.3, deduplicated. It does not need to be exhaustive; it needs to be enough that a real divergence has a fair chance of being caught.
- The oracle does not redefine layer-internal assertions — those stay in their owning harness. The oracle only diffs final outputs.
- A divergence does not block the oracle from continuing to the next input; the run produces a complete report.
- Documented in a single place (likely the M8 goal file's retrospective on close, or a short note added to the Makefile target's help text) so the next person debugging a playground regression discovers it.

Out of scope: fixing any actual divergences the oracle finds on first run — those are separate tickets, scoped to whichever layer owns the bug. Continuous-integration wiring (running the oracle in CI on every PR is a follow-up if the oracle proves stable enough; not required to close M8).

## Dependencies

[M8.1](M8.1-wasm-boundary-harness.md), [M8.2](M8.2-worker-local-harness.md), [M8.3](M8.3-frontend-transport-harness.md). All three must be in place; the oracle has no value without them.

## Verification

- Run the oracle on the shared corpus. Either it reports full agreement, or it reports a real divergence (in which case open a follow-up ticket against the named layer and re-run after the fix).
- Hand-introduce a divergence at each layer in turn (mutate the wasm JSON, mutate the Worker response, mutate the frontend transport) and confirm the oracle names the correct boundary each time.
- `go test ./...` and `go vet ./...` pass.
