# M9.4 · `/goal-dispatch` command

**Status:** todo
**Goal:** M9
**Size:** medium

## What

New slash command that takes a goal ID, refuses to proceed when the goal's `Paths:` overlap an `active` or `ongoing` goal, and otherwise prepares a worktree on the goal branch ready for an agent session. M9.4 prepares the environment; it does not spawn the agent process or open the PR — those remain the human's actions or follow-up automations.

## Scope

- **Artifacts created.**
  - `.claude/commands/goal-dispatch.md` — slash-command prose that invokes the script and reports its output.
  - `tools/goal-dispatch.sh` — bash script doing the actual work. `tools/` directory created if absent.

- **Invocation.** `/goal-dispatch M<N>`. Single argument: goal ID.

- **Sequence.**
  1. Validate `kanban/goals/M<N>.md` exists. Refuse with goal-not-found message if not.
  2. Parse goal's `**Status:**`. If not `active`, refuse and report the actual status.
  3. Parse goal's `**Paths:**`. If absent, refuse and direct user to add Paths (or re-run `/goal-define` for the goal).
  4. Glob `kanban/goals/M*.md`, parse each one's `Status:` + `Paths:` (skip the dispatched goal itself, skip files without Paths). Filter to status `active` or `ongoing`.
  5. Compute set-intersection overlap: enumerate files in the working tree matching any of the dispatched goal's globs, and check whether any of those files also match any glob from another active/ongoing goal. If any overlap, refuse with the conflicting goal name and the specific (this-goal-glob, other-goal-glob, conflicting-file) tuples.
  6. Derive `<slug>` from the goal file's first-line title (`# M<N> — <title>`): lowercase, hyphenate spaces, drop punctuation. Branch name is `goal/M<N>-<slug>`.
  7. Worktree path is `../void-slice-M<N>-<slug>` relative to the repo root. If that path already exists, refuse with "worktree already exists; resume there or remove it first."
  8. Branch handling: `git fetch origin main` first. If `goal/M<N>-<slug>` exists locally or on origin, use it. Otherwise create from `origin/main`.
  9. Do *not* auto-rebase if the goal branch is behind `origin/main` — surface to the user.
  10. Create the worktree: `git worktree add <path> <branch>`.
  11. Print next-step instructions: the worktree path, the suggested invocation (`cd <path> && claude` or equivalent), and a reminder that `/implement-ticket M<N>.<n>` is the entry point for ticket work.

- **Glob library.** Bash + `git ls-files` + a globbing utility (e.g. `find` with `-path`, or shelling out to a small Go utility, or using `python -c` if available). Decided at implementation time. Constraint: the glob semantics must match M9.1's doublestar convention (`**`, `*`, `?`).

- **No PR creation.** The first push from the goal branch (by `/implement-ticket` or manually) opens the PR via GitHub's auto-create URL or `gh pr create`. Auto-PR-from-dispatch is a defensible follow-up but out of M9.4 scope.

- **No agent spawn.** The dispatcher prints instructions; the human starts the Claude Code session in the worktree. Auto-spawn is a defensible follow-up.

- **Documentation.** A brief mention in `kanban/README.md` lifecycle section: `/goal-dispatch` is the entry point for starting work on a goal.

## Dependencies

M9.1 (Paths field exists in the schema). Soft on M9.3 (branch convention codified) — implementable independently but the convention has to match.

## Verification

- `/goal-dispatch <id>` on a clean, non-overlapping goal creates `goal/M<N>-<slug>` and the sibling worktree, and prints next-step instructions.
- `/goal-dispatch <id>` on a goal whose Paths overlap M9 (or any active/ongoing goal) refuses and names the conflicting goal + the offending file.
- `/goal-dispatch <id>` on a goal with `Status: parked`/`done`/missing refuses and reports the status.
- `/goal-dispatch <id>` on a goal missing the `Paths:` field refuses and tells the user to add it.
- Re-running `/goal-dispatch M9` (which has an existing branch and worktree) refuses with the worktree-exists message.
- The worktree, when entered, is on `goal/M<N>-<slug>` and has the same content as the goal branch tip.

## Out of scope (intentionally deferred)

- Auto-spawning a Claude Code agent in the new worktree — the human launches the session.
- Auto-opening the PR for the goal branch — first push or manual creation.
- Auto-rebasing the goal branch onto `main` if behind — surface only, never silent rewrite.
- Worktree teardown / cleanup tooling — separate concern (`/goal-close` or similar, future).
- Refactoring `/goal-define`'s overlap-check (M9.2) to call this script — a follow-up once M9.4 is stable.
