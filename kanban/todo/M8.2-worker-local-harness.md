# M8.2 · Worker-local harness

**Status:** todo
**Goal:** M8
**Size:** medium
**Blocks:** M8.4

## What

A harness that exercises [worker/index.js](../../worker/index.js) end-to-end on the developer's machine — no `wrangler deploy`, no preview URL — and pins the HTTP plumbing: routing, methods, content-type filter, body cap, multipart parsing, CORS headers, OPTIONS, and the rate-limiter toggle. When this harness disagrees with the WASM-boundary harness from M8.1, the bug is in the Worker glue, not in the linter or the wasm export.

## Scope

What must end up true:

- A harness exists that brings the Worker up locally (e.g. `wrangler dev` or an in-process Miniflare equivalent) and drives real HTTP requests at it.
- Each branch in `handleLint` and the top-level router in [worker/index.js:155-189](../../worker/index.js#L155-L189) has a corresponding case:
  - `GET /health` → 200 JSON.
  - `POST /lint` with `application/octet-stream` → 200 JSON, body matches what the WASM-boundary harness produces for the same input.
  - `OPTIONS /lint` → 204 with the expected `Access-Control-*` headers.
  - `GET /lint` and other non-POST methods → 405.
  - Disallowed `Content-Type` (e.g. `image/png`) → 415.
  - Body over `MAX_BODY_BYTES` → 413.
  - `multipart/form-data` with one file part → 200; with no file part → 400.
  - Unknown path → 404.
  - With `RATE_LIMITER` bound and exhausted → 429; with it unbound, the same request → 200.
  - CORS headers present and reflect `ALLOWED_ORIGIN` env (`*` and a specific origin both covered).
- The harness reuses (does not re-invent) the `(filename, src)` fixtures from M8.1 for the body-success cases, so divergence between the two layers is meaningful.
- Failure messages localize the problem to the Worker glue: which request, which header or status diverged.
- Wired into the same `make`-equivalent entry as M8.1.
- Does not require a Cloudflare account or any deployed resource. Runs offline.

Out of scope: linter correctness (M8.1 owns it). Frontend transport (M8.3). Production rate-limiter behavior under real load.

## Dependencies

None hard. Sharing fixtures with M8.1 is a coordination point but not a build-time dependency — either ticket can land first; whichever lands second adopts the fixture layout the first chose.

## Verification

- The harness boots the Worker locally and all listed cases pass.
- Hand-introduce a divergence (e.g. drop the `Vary: Origin` header, or change `MAX_BODY_BYTES`) and confirm the harness fails with a message naming the request and the specific assertion that broke.
- `go test ./...` and `go vet ./...` pass.
