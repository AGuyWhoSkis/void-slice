# M7.6 · `compatibility_date` discipline

**Status:** todo
**Goal:** M7
**Size:** small

## What

[wrangler.toml:3](../../wrangler.toml#L3) sets `compatibility_date = "2025-09-01"`. There's no mechanism to notice when this date drifts months out of date — and a stale `compatibility_date` means the Worker silently misses Workers-runtime improvements (perf, bug fixes, new APIs gated behind newer dates). M7.6 adds a CI check that flags when the `compatibility_date` is older than a documented threshold, so the bump becomes a deliberate decision (review the changelog, tick the date forward) instead of silent drift.

## Scope

What must end up true:

- A CI step (in `.github/workflows/ci.yml`, in the `test` or `lint` job, or its own job — implementer's call) parses `compatibility_date` from `wrangler.toml` and fails if the date is older than a threshold (e.g. 90 or 180 days from `today`). Pick one threshold and document it inline.
- The failure message is actionable: it names the current date, the threshold, the action to take ("bump the date in `wrangler.toml` after reviewing https://developers.cloudflare.com/workers/configuration/compatibility-dates/"), and links to the Workers compat-date changelog.
- The check runs on every PR. It can run on `push: main` too, but the PR run is the gate that matters.
- The threshold is hard-coded — no env var, no input.
- Bumping `compatibility_date` requires no code changes beyond the `wrangler.toml` edit and a passing CI run.

Out of scope: an automated PR that bumps the date (a human should review the changelog before bumping). A semver-style policy. A check that compares against the latest Workers compat-date — that requires fetching from Cloudflare during CI, which adds an external dependency for low value.

## Dependencies

None.

## Verification

- Run the new CI step locally (extracted as a script or with `act`); confirm it passes today (the date isn't yet stale).
- Temporarily edit `wrangler.toml` to set `compatibility_date = "2024-01-01"`; rerun the check; confirm it fails with the actionable message. Revert.
- The check fits cleanly into an existing job (no new top-level CI job unless justified by the implementer).
