# M7.7 · Workers logs durable export

**Status:** todo
**Goal:** M7
**Size:** small-to-medium

## What

The Worker logs structured JSON per request ([worker/index.js:179-186](../../worker/index.js#L179-L186)) and `[observability]` is enabled in `wrangler.toml`, which keeps logs queryable in the Cloudflare dashboard for a few days at the platform's default retention. For post-mortems, regression hunts, and traffic-pattern analysis, that window is too short. M7.7 configures Workers Logs / Logpush to forward request logs to a durable destination (R2 bucket, by default) so logs survive past the platform's retention window.

## Scope

What must end up true:

- `wrangler.toml` (or an equivalent dashboard-configured Logpush job, documented in `wrangler.toml` comments if the configuration lives outside the file) ships request logs to a durable destination. R2 is the recommended default — same account, same billing, no additional vendor.
- The destination, retention policy, and sample rate (if any) are documented inline in `wrangler.toml`. A reader should know where the logs end up without consulting an external runbook.
- The exported logs include, at minimum, what `console.log` emits today: method, path, status, duration. Adding more fields is fine but not required.
- Export is enabled for the production Worker. Preview Workers are out of scope — short-lived previews don't accumulate enough log volume to justify exporting.
- Cost / volume implications are noted: the existing $5/mo Workers Paid plan covers Logpush, but R2 storage and egress are billed separately. Document the expected ballpark (likely cents per month at current traffic).
- A retrieval recipe is documented: how to download a day's logs from the destination and grep them. One paragraph in `wrangler.toml` comments or a `worker/LOGS.md` is sufficient — the bar is "a future debugger can find the logs without messaging me".

Out of scope: log shipping to a third-party SaaS (Datadog, Honeycomb, etc.) — R2 is sufficient for this project's scale. Real-time alerting on log content. Schema beyond the existing per-request JSON.

## Dependencies

None.

## Verification

- After landing, hit the prod Worker `/health` and `/lint` endpoints a handful of times. Within the platform's flush window (typically a few minutes), confirm the corresponding log lines appear in R2 (or whichever destination is chosen).
- The R2 bucket / destination is provisioned and visible in the Cloudflare dashboard. Bucket name and region are documented.
- A test retrieval (download yesterday's prefix, grep for one of the test request paths) succeeds.
- `wrangler dev` is unaffected — local development still emits logs to stdout as today.
