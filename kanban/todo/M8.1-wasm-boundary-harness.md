# M8.1 · WASM-boundary harness

**Status:** todo
**Goal:** M8
**Size:** small-to-medium
**Blocks:** M8.4

## What

A test harness that loads `worker/voidslice.wasm` and calls `voidsliceLint(filename, src)` directly — no Worker, no HTTP, no frontend. Pins the Go→JS export contract: argument coercion, return value shape, the `WORKER_HARNESS` error JSON path. When this harness disagrees with native `internal/lint`, the bug is in the wasm boundary itself, not in any layer above it.

## Scope

What must end up true:

- A harness binary or test entry point exists that, given `(filename, src)`, returns the same JSON shape that the deployed Worker would return for `/lint` — but obtained by calling the wasm export directly, with no Worker code in the path.
- The harness runs offline against a freshly-built `worker/voidslice.wasm`. No deploy, no `wrangler dev`, no network.
- The harness exercises both the success path and the error-JSON path emitted by [cmd/voidslice-wasm/main.go:41-48](../../cmd/voidslice-wasm/main.go#L41-L48) (e.g. when called with the wrong argument count).
- It runs against a small fixture set covering: a clean file, a file with a known `VALIDATE_*` warning, a file with a hard scan error, and an empty input. Reusing inputs already present under `testdata/` is fine; do not invent a new corpus.
- Failure messages localize the problem to the wasm boundary: which input, which field of the returned JSON diverged from the native-Go reference.
- Wired into `make` (or an equivalent already-discoverable target) so a developer can run it without consulting documentation.
- The harness build is not a prerequisite of `go test ./...` (it owns its own toolchain — Node + `wasm_exec.js`); the Go test suite stays self-contained.

Out of scope: HTTP plumbing, multipart, CORS, rate limiting (those live in M8.2). Frontend transport (M8.3). Cross-layer differential — M8.4 composes this harness with the others.

## Dependencies

None — this is the lowest of the three middle layers and can land first.

## Verification

- `worker/build.sh` produces `voidslice.wasm`; the harness loads it and the four fixtures pass.
- Hand-introduce a divergence (e.g. mutate the JSON template in [cmd/voidslice-wasm/main.go:47](../../cmd/voidslice-wasm/main.go#L47) to drop the `code` field) and confirm the harness fails with a message naming the input and the missing field, not a generic "mismatch".
- `go test ./...` and `go vet ./...` pass.
