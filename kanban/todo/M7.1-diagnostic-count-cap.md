# M7.1 · Diagnostic-count cap

**Status:** todo
**Goal:** M7
**Size:** small

## What

A pathological input — e.g. a deeply nested or syntactically broken file — can cause the parse / validate pipeline to emit an unbounded number of diagnostics. In the deployed Worker, the diagnostic slice is held in memory before JSON serialization; an unbounded slice is the most plausible OOM vector for a 128 MB Worker isolate. M7.1 puts a hard ceiling on how many diagnostics a single lint can emit, plus a sentinel "diagnostic limit reached" entry so callers know the result is truncated, not exhaustive.

## Scope

What must end up true:

- A documented constant defines the maximum number of diagnostics a single `WalkEntities` / `ValidateEntities` call can emit. Pick a number comfortably above any legitimate file's count in `testdata/corpus-mini/` but well below what would OOM a Worker isolate.
- Once the cap is reached, the walker stops emitting further diagnostics and appends one final sentinel diagnostic with a stable code (e.g. `LIMIT_DIAGNOSTICS_TRUNCATED`) and a message that names the limit. Internal parsing/validation may continue if cheap, but no more diagnostics flow to the handler.
- The cap applies uniformly: lex diagnostics, structural diagnostics, `VALIDATE_*` warnings — all count against the same budget.
- A test fixture demonstrates the cap kicks in (synthesize an input that exceeds the limit) and that the truncation sentinel is the final entry.
- All existing golden-file tests still pass — the limit must be high enough that no file in `testdata/corpus-mini/` triggers truncation.

Out of scope: caller-side handling of the truncation sentinel (Worker, frontend, CLI continue to render diagnostics verbatim). A configurable cap (env var / flag) — pick one number, hard-code it.

## Dependencies

None.

## Verification

- `go test ./...` passes, including the new cap fixture and all existing goldens.
- Hand-construct an input that exceeds the cap; run the CLI against it; confirm the rendered output ends with the truncation sentinel and contains exactly `cap+1` diagnostics.
- `grep` confirms no caller in `internal/` or `cmd/` short-circuits on the new sentinel code (M7.1 does not change rendering behavior).
