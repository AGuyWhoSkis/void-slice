# M12.19 · Scanner COMMENT_BLOCK Span omits closing `/`

**Status:** todo
**Goal:** M12
**Size:** small
**Origin:** M12.15 — implementation-time discovery

## What

`internal/scan/scan.go:140` emits `COMMENT_BLOCK` tokens with
`Span.End = i_blkQuot + 1`, where `i_blkQuot` is the index of the `*`
in the closing `*/`. So `Span.End` points at the `/` byte, and
`src[Span.Start:Span.End]` reads `/* x *` — missing the closing `/`.
The outer loop's post-emit `i = i_blkQuot + 1` plus `continue mainLoop`
then increments past the `/`, so the byte gets consumed but never
folded into any token.

This violates the spans' documented contract:

```go
type Span struct {
    Start int // byte offset, inclusive
    End   int // byte offset, exclusive
}
```

For COMMENT_BLOCK, `End` should be `i_blkQuot + 2` (the position one
past `/`), making `src[Start:End]` return the full `/* … */`.

The M12.15 lexinvariance harness ran into this: its skip-mask and
inter-token-gap calculations both treat `[Start, End)` as the comment's
full extent, then the `/` byte became a "free byte" that the collapse
variant ate, breaking the comment. The harness compensates locally
with an `effectiveTokenEnd` helper. That helper exists to paper over
this scanner bug; the fix belongs in the scanner.

Discovery doesn't hit this because it only mutates structural bytes
(`{ } ; = [ ]`) and `/` isn't in that set. Any future caller doing
byte-aware comment skipping will hit it.

## Scope

- Change `internal/scan/scan.go:140` to `emitToken(TokenKind.COMMENT_BLOCK, i, i_blkQuot+2)`.
- Update any scanner tests that pin the old end-offset (find via
  `grep -nr CommentBlock internal/scan/`).
- Remove `effectiveTokenEnd` from `internal/harness/lexinvariance/lexinvariance.go`
  and replace its call sites with plain `t.Span.End`. The skip mask
  and the inter-token gap calculation both simplify back to discovery's
  shape.
- Spot-check the discovery harness's `buildCommentQuoteMask` — same
  shape, no behavioral change expected (discovery never mutates `/`),
  but the mask now correctly covers the full comment.

### Out of scope

- Any other scanner span quirks that aren't this exact off-by-one.
  Audit them under a separate ticket if discovery or lexinvariance
  surface more cases.

## Dependencies

- M12.15 (the `effectiveTokenEnd` workaround lives in that ticket's
  code; removing it is part of this fix).
