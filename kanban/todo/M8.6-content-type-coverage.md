# M8.6 · Exhaustive Content-Type coverage in worker-harness

**Status:** todo
**Goal:** M8
**Size:** small
**Origin:** M8.2

## What

[worker/index.js](../../worker/index.js)'s `isAllowedContentType` has roughly
ten allow/deny entries (empty, `application/octet-stream`, `text/*`,
`multipart/form-data`, `image/*`, `audio/*`, `video/*`, `application/zip`,
`application/gzip`, `application/x-gzip`, `application/x-tar`,
`application/pdf`, plus the fall-through `true`). The M8.2 worker-harness
spot-checks two: `application/octet-stream` (allow) and `image/png` (deny).
A regression that flips a single row — say, accidentally adding
`application/json` to the deny list, or dropping `text/plain` from the
allow path — would not be caught.

## Scope

What must end up true:

- Add a content-type sweep case to `worker/harness/worker-harness.mjs`
  that drives one request per branch in `isAllowedContentType`, asserting
  the expected status (200 for allow, 415 for deny, plus the wildcard
  `text/*` and `multipart/form-data` prefixes).
- Use the smallest valid body (the existing `empty-input` fixture) so the
  sweep runs in milliseconds.
- Keep failure messages localized in the same `case=<ct> field=status
  got=<x> want=<y>` format.

Out of scope: parsing oddities (`Content-Type: application/octet-stream;
charset=utf-8`) — already covered by the `head = ct.split(";")[0]` path,
add only if a regression motivates it.

## Dependencies

- M8.2 (this ticket's origin; landed).

## Verification

- Add the sweep, run `make worker-harness`, all rows pass.
- Hand-introduce a divergence (e.g. add `application/json` to the deny
  list); confirm the harness fails with a message naming the specific
  content-type and `field=status`.
- `go test ./...` and `go vet ./...` pass.
