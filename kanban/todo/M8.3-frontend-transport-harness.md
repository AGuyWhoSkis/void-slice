# M8.3 · Frontend-transport harness

**Status:** todo
**Goal:** M8
**Size:** small
**Blocks:** M8.4

## What

A harness that exercises [web/src/api.ts](../../web/src/api.ts) — specifically `lintFile()` — against a stub `fetch`, with no React, no Vite dev server, no DOM. Pins URL construction, request shape, status handling, and error mapping. Stays UI-agnostic per the M8 scope ("excludes UI/component tests in the frontend, deliberately").

## Scope

What must end up true:

- A harness exists under `web/` (test file alongside `api.ts`, or a sibling spec runner — whichever fits the existing frontend test setup; if none exists yet, choose the lightest tool that integrates with the current Vite/TS toolchain).
- `globalThis.fetch` is stubbed; the harness asserts on the request that `lintFile()` issues and on the `LintResponse` it returns.
- Cases covered:
  - URL is `${API_URL}/lint?filename=<encoded>`. `filename` is URL-encoded (test with a name containing `?`, `&`, and a space).
  - Method is `POST`; `Content-Type: application/octet-stream`; body is the raw `src` string (not JSON-wrapped).
  - 200 with valid JSON body → resolves to a `LintResponse` with the diagnostics array intact.
  - Non-2xx with a text body → rejects with an `Error` whose message includes the status code and the body text.
  - Non-2xx with `res.text()` itself throwing → rejects with an `Error` whose message includes the status code and the `statusText`.
  - `VITE_API_URL` unset → falls back to `http://localhost:8080` (covered by reading the value from `api.ts`'s defaulting branch, not by mutating `import.meta.env` at runtime if the test runner makes that awkward).
- The harness runs offline; it does not hit M8.2's Worker harness or any network.
- Wired into the frontend's existing test command (or one introduced by this ticket if none exists), so a developer runs it without consulting documentation.

Out of scope: React component tests, the file-drop UI, samples picker, anything in [web/src/components/](../../web/src/components/). The goal explicitly excludes UI tests for durability across UI churn.

## Dependencies

None. Independent of M8.1 and M8.2 — different file, different toolchain.

## Verification

- The harness runs and all listed cases pass.
- Hand-introduce a divergence (e.g. change `lintFile` to use `GET`, or to JSON-stringify the body) and confirm the harness fails with a message naming the assertion that broke.
- `go test ./...` and `go vet ./...` pass.
