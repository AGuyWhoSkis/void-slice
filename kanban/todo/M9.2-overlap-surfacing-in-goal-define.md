# M9.2 · Overlap surfacing in `/goal-define`

**Status:** todo
**Goal:** M9
**Size:** medium

## What

Wire an overlap check into the `/goal-define` conversation so the human sees collisions with in-flight goals at the moment of definition, not later when `/goal-dispatch` refuses to spawn. The skill also writes the `Paths:` field into the new goal file as part of confirming the draft.

## Scope

- `/goal-define` prompts for or derives `Paths:` during the scope conversation
- Skill reads `**Paths:**` from active goals and reports overlap in chat before drafting the file
- Generated goal file includes the `Paths:` field
- Surfacing is informational — the human decides whether to proceed; no automatic blocking

## Dependencies

M9.1 (schema must exist).

## Verification

Running `/goal-define` on a goal whose paths overlap an in-flight goal surfaces the collision in the conversation, naming the conflicting goal. The produced goal file contains a populated `Paths:` field.
