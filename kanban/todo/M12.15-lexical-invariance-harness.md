# M12.15 · Lexical-equivalence invariance harness (spike)

**Status:** todo
**Goal:** M12
**Size:** medium
**Origin:** M12 chat — whitespace-only diff on the same unterminated-quote bug produced 8 diagnostics vs 2

## What

The linter's recovery and parser heuristics are exercised by current
harnesses only along structural-byte axes. M12.9–M12.14 enumerate
deletes, inserts, and replaces of `{ } ; = [ ]`. None of them touch
whitespace or comments — bytes the grammar treats as insignificant.
A chat-driven sanity check found that the same logical input emits
*8 diagnostics in one whitespace layout and 2 in another*, both for
an unterminated quote at the same source position. The cascade is
gated purely by whether the `}` after the open quote sits at column 0
or is indented — bytes the grammar should treat as equivalent. The
locality harness can't see this (no whitespace axis). The discovery
harness can't see this (both forms are valid inputs; neither is a
single-byte mutation of the other).

The axiom this spike anchors to is the M12 axiom restated against a
new axis: *a diagnostic should never depend on bytes the grammar
treats as insignificant*. Equivalently — two inputs whose token
streams are identical after removing whitespace and comments should
produce the same diagnostic-code multiset.

This ticket is a spike: it lands the harness and a sweep report,
then files follow-up tickets per finding shape. It does **not** fix
any divergence the report surfaces. Out of scope is deliberate — the
spike is gating, the fixes are downstream.

### Concrete known case the harness must catch

```text
// V1 — 8 diagnostics
Version 1
component {
	cpntTest myTest {
		edit = {
			m_items = {
				num = 2;
				item[0] = { m_val = "a"; }
				item[1] = { x_val = "b;
}
			}
		}
	}
}
```

```text
// V2 — 2 diagnostics (identical to V1 minus 12 spaces before `}` on line 9)
Version 1
component {
	cpntTest myTest {
		edit = {
			m_items = {
				num = 2;
				item[0] = { m_val = "a"; }
				item[1] = { x_val = "b;
            }
			}
		}
	}
}
```

V1 emits `LINT_VE_INCONSISTENCY`, `VOID_SCAN unterminated quote`, plus
3× `PARSE_UNTERMINATED_OBJECT` and 3× `PARSE_UNEXPECTED_TOKEN`. V2
emits only `LINT_VE_INCONSISTENCY` and the one quote diagnostic. The
6 extra diagnostics in V1 are cascade — they would re-validate clean
once the quote is closed, which is exactly the shape M12 was chartered
to eliminate. The harness must surface this case as a divergence.

## Scope

### Package layout

Add `internal/harness/lexinvariance/` mirroring the shape of
[`internal/harness/discovery/`](../../internal/harness/discovery/):

- `lexinvariance.go` — production API. Exposes `Transform(src, kind) []byte`,
  `Scan(path, src, opts) []Finding`, and the shared `Finding` /
  `Options` types. No build tag.
- `lexinvariance_test.go` (build tag `lexinvariance`) — corpus driver.
  Walks `testdata/golden/` and `testdata/cascades/`, generates K
  variants per file, compares diagnostic-code multisets, writes
  `lexinvariance-report.md` at repo root.
- `lexinvariance_unit_test.go` (no build tag) — synthetic-fixture tests
  pinning each transform's contract and the V1/V2 known-case
  detection.

Follow [`internal/harness/discovery/discovery.go`](../../internal/harness/discovery/discovery.go)
for ordering, sampling, and report conventions. Reuse
`makeDiagKeySet` / `diagsMatchBaseline`-shaped helpers conceptually,
but key on diagnostic *code* only (not span) — span equality is too
strict when whitespace shifts offsets.

### Transform kinds (v1)

Define a `TransformKind` enum. The harness applies one transform per
variant — composition is out of scope for the spike.

1. **`TransformReindent`** — replace each line's leading whitespace
   with a deterministically-varied alternative (e.g. swap tab runs
   for 2/4/8-space runs, or vice versa). One variant per file per
   indent-style choice; pick 2 alternatives that differ from the
   source's existing style.
2. **`TransformTabSpace`** — convert all tabs to spaces and all
   runs of 2/4/8 leading spaces to a single tab (two variants:
   tabs-to-spaces, spaces-to-tabs).
3. **`TransformInterTokenPadding`** — between each adjacent token
   pair (using the same gap-positions discovery's inserts use),
   set the gap to a deterministic alternate width (e.g. collapse
   to a single space, or expand to N spaces). Two variants.
4. **`TransformBlankLineJitter`** — add or remove a blank line
   between top-level constructs. Detect "top-level" as a line whose
   first non-whitespace byte is at column 1. Two variants.

Each transform's contract: **the post-transform scan token stream,
with whitespace and comments removed, equals the pre-transform stream
under the same filter.** A `TestTransformPreservesTokens` unit test
per kind, run on a small synthetic fixture, pins this — if a transform
ever desyncs, every downstream divergence claim becomes meaningless.

Note: bytes *inside* a `QUOTE_LITERAL` or comment token must not be
edited by any transform. Use the same comment/quote skip mask
[`internal/harness/discovery/discovery.go:buildCommentQuoteMask`](../../internal/harness/discovery/discovery.go)
uses (or extract it to a shared helper if cleaner — that refactor is in
scope if light).

### Scan + divergence

```go
type Finding struct {
    Path       string
    Transform  TransformKind
    VariantIdx int    // 0..K-1 per kind, for reproducibility
    BaselineCodes []string // sorted code multiset
    VariantCodes  []string
    // CodeDiff: codes present in one but not the other, signed by which side.
    CodeDiff []SignedCode
}
```

A finding is emitted iff `BaselineCodes != VariantCodes` (multiset
equality on diagnostic code only). Per-file: lint baseline once, then
lint each variant, diff, append findings.

### Driver + report

`lexinvariance_test.go` (build tag) walks the same corpus the discovery
driver does. Per file: skip if baseline lint errored (rare); otherwise
generate ~8 variants (4 kinds × ~2 each), lint, diff, accumulate.

Render `lexinvariance-report.md` with the same shape as
`discovery-report.md`:

- Header: files scanned, total variants applied, total findings,
  per-transform divergence counts.
- Findings: sorted by divergence size desc, then by path. Each entry
  shows transform kind, baseline-vs-variant code lists, and a 3-line
  diag sample from each side.

The V1/V2 case must appear in the report (or in a unit test if it's
not naturally in the corpus — add a synthetic fixture under
`testdata/cascades/lexinvariance/` if needed; that fixture path is
inside M12's `Paths:`).

### Makefile + CI

The harness joins the build-tagged sweep family. Add a
`make lexinvariance` target alongside `make harnesses` (look at the
existing `make harnesses` recipe for the pattern). **Do not** add it
to the default `make harnesses` aggregate yet — it produces a triage
report, not a pass/fail gate, same as discovery. CI doesn't run it
until calibration lands.

## Dependencies

None (this spike is self-contained — built on `internal/scan` and
`internal/lint` primitives that have existed since M0).

## Verification

- `go test ./...` and `go vet ./...` clean.
- `go test -tags=lexinvariance ./internal/harness/lexinvariance/` runs
  to completion within a 10-min budget. The discovery harness sweep
  takes ~5 min on this corpus at ~98K mutations; lexinvariance applies
  ~8 variants per file × 67 files ≈ 540 variants — orders of magnitude
  fewer lint calls, expect well under 1 min.
- `lexinvariance-report.md` is regenerated; the header reports
  non-zero divergences (the V1/V2 shape alone guarantees this); the
  per-transform breakdown shows at least which kinds surface signal.
- Unit tests pin: (a) each transform preserves the
  whitespace-and-comment-filtered token stream on a synthetic
  fixture; (b) the V1/V2 known case produces a finding under
  `TransformReindent` or `TransformBlankLineJitter` (whichever the
  natural fit is — pick when the harness lands).
- `make harnesses` is unaffected — the new target is opt-in.
- **Memo deliverable.** A one-paragraph classification of finding
  shapes (recovery-path divergence, column-sensitive diagnostic,
  tab/space sensitivity, etc.) recorded in the close commit body
  alongside the divergence counts. This is the spike's primary
  output; the harness itself is the means to it.

## Out of scope

- **Fixing anything the report surfaces.** Each shape becomes a
  follow-up ticket via the standard `/crud-ticket` propose flow.
  This ticket files no fixes in `internal/scan/`, `internal/parse/`,
  or `internal/validate/`.
- **Token-level mutation** (replacing one IDENT for another, swapping
  QUOTE_LITERAL contents). Separate goal — see
  [`draft-goal-define-token-level-mutation.md`](../../draft-goal-define-token-level-mutation.md).
- **Composed transforms** (apply two kinds in sequence). Single-
  transform variants are enough to surface the shapes; composition
  multiplies report noise without obvious benefit at this stage.
- **Comment-insertion transforms** (e.g. inject `// foo` between
  tokens). Plausible 5th transform kind, but deferred — it changes
  the *comment* token stream while leaving whitespace alone, so it
  tests a different sub-property and deserves its own ticket if any
  of the 4 v1 kinds surfaces too little signal to motivate it.
- **Formatter round-trip equivalence.** Would require a formatter
  the project doesn't have. Out of M12's mandate.
- **Calibrating the harness as a CI gate.** Discovery and locality
  show the pattern — land prospecting, then tighten. Calibration is
  a successor ticket if the report justifies one.
