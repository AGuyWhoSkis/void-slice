# M6.4 · Protect `main`

**Status:** todo
**Goal:** M6
**Size:** small
**Blocks:** nothing

## What

Make `main` non-pushable. After this lands, the only way to update production is to open a PR, pass all four required checks, and merge.

## Scope

Configure once via `gh` CLI; document the exact invocation in this ticket body for reproducibility (no in-repo ruleset YAML, no third-party action — overkill for a small project).

**Rules:**
- Required status checks (strict — branch must be up-to-date with `main`):
  - `test`
  - `lint`
  - `build`
  - `preview-deploy`
- `required_linear_history = true` (forces squash or rebase merges; matches the "concise commit messages" convention in CLAUDE.md).
- `allow_force_pushes = false`.
- `allow_deletions = false`.
- `enforce_admins = true` — admin bypass OFF. The point of M6 is "main is no longer push-able"; an exception for the only admin defeats it. Easy to flip back if locked out.
- `required_pull_request_reviews.required_approving_review_count = 0` — single-author project today. Flip to 1 the moment a second contributor lands.

**Suggested invocation** (record the exact command in the `## Completion` section once run):
```
gh api -X PUT repos/:owner/:repo/branches/main/protection \
  -F required_status_checks.strict=true \
  -f 'required_status_checks.contexts[]=test' \
  -f 'required_status_checks.contexts[]=lint' \
  -f 'required_status_checks.contexts[]=build' \
  -f 'required_status_checks.contexts[]=preview-deploy' \
  -F enforce_admins=true \
  -F required_pull_request_reviews.required_approving_review_count=0 \
  -F required_linear_history=true \
  -F allow_force_pushes=false \
  -F allow_deletions=false \
  -F restrictions= 
```
The `restrictions=` empty value is required — the API rejects the call if the field is omitted entirely. Verify against [GitHub's branch-protection API docs](https://docs.github.com/en/rest/branches/branch-protection) before running.

## Notes

- **Fork PRs interaction.** `preview-deploy` is skipped on fork PRs (M6.2 gates on same-repo). Skipped jobs are not "passed" in branch-protection semantics, so fork PRs will be blocked from merging until the project explicitly supports them. Acceptable today.

## Dependencies

[M6.2](M6.2-preview-deploy-job.md) (the `preview-deploy` job must exist before it can be a required check).

## Verification

- `git push origin main` from a clean clone → rejected with "protected branch" error.
- Open a PR; the "Merge" button is gated until the four checks complete green.
- Force-push attempts (`git push --force-with-lease`) → rejected.
- `git push origin :main` → rejected.
- Admin clicks "merge" without all checks green → rejected (because `enforce_admins=true`).
