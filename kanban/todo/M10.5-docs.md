# M10.5 · Docs: CLAUDE.md, kanban/README.md, crud-ticket

**Status:** todo
**Goal:** M10
**Size:** small

## What
Document the nit substrate end-to-end: capture, surface, adoption, lifecycle, file formats. Update the three docs that need to know about it.

## Scope
- Edit `CLAUDE.md`:
  - New subsection `### Nits` under `## Kanban`, placed after `### Branches and merge protocol` and before `### CI-feedback loop`.
  - Covers, in order: what a nit is (a tiny single-edit chore captured during another goal's work); where nits live (long-lived `nits` branch + sibling `../void-slice-nits/` worktree, bootstrapped via `tools/nits-bootstrap.sh`); capture (`/nit "<description>"`); surface (`/goal-define` lists pending nits read-only); adoption (`/goal-slice` claims via atomic push and materializes each as a ticket with `**Origin:** nit-<timestamp>`); the Paths-subset rule (an adopted nit's `Paths:` must be ⊆ adopting goal's `Paths:` — no bypass of M9's contract); the sizing bound (one file, one conceptual change; bigger = file a ticket directly).
- Edit `kanban/README.md`:
  - New `## Nits` section placed between `## Goals` and `## Columns`.
  - Covers: substrate location, lifecycle (`filed → claimed → ticketed → landed`), the `**Origin:** nit-<timestamp>` field on materialized tickets.
  - Includes a sample nit-file markdown (the format from M10.2's scope) in a fenced code block.
- Edit `.claude/commands/crud-ticket.md`:
  - In the PROPOSE section, mention that `**Origin:** nit-<timestamp>` is a valid origin alongside `<originating-ticket-id>` for tickets materialized from nits.

## Dependencies
None — docs can land in parallel with the implementation tickets, but should land before M10.6 so the system is documented when the canonical first nit is filed.

## Verification
- `grep -n "^### Nits" CLAUDE.md` returns exactly one hit.
- `grep -n "^## Nits" kanban/README.md` returns exactly one hit.
- `grep -n "Origin.*nit-" .claude/commands/crud-ticket.md` returns at least one hit.
- A reader who knows nothing about nits can, from `CLAUDE.md` alone, learn: (1) what a nit is, (2) how to file one, (3) how it eventually lands, (4) the sizing bound.

- Tutorial / walkthrough docs — terse reference doc fits the project's style. The slash-command `.md` files are the operational manual.
