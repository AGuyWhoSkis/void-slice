# M17.5 · Rewrite VOID_SCAN unterminated-quote message text

**Status:** todo
**Goal:** M17
**Size:** small
**Origin:** [M17-root-causes.md §3 ticket 3](../goals/M17-root-causes.md)

## What

The scanner emits the diagnostic message `unterminated quote` at two sites — [`internal/scan/scan.go:100`](../../internal/scan/scan.go#L100) (the newline-terminated unterminated quote, M12.3's path) and [`internal/scan/scan.go:107`](../../internal/scan/scan.go#L107) (the EOF-terminated unterminated quote, fall-through case). The message reads as scanner-internal vocabulary (a "quote" without context, a verb-less "unterminated"). When the SC-2 family fires — a quote-byte flip that turns a `"` into `'` and creates an orphan-quote run — the user sees `[VOID_SCAN] unterminated quote` and is left to infer what action to take.

Separately from M17.6's open question on the SC-2 cluster *count*, the message *text* is a fixable user-side gripe today. It doesn't change the diagnostic count, the code, the span, or the shape of any cluster — it changes what the user reads.

Change both sites' message string to the literal:

```
unterminated string literal — check for a missing '"'
```

(em-dash, single quotes around the literal `"` so the message renders cleanly in both pretty and JSON output, no trailing punctuation.)

## Scope

- **Edit [`internal/scan/scan.go`](../../internal/scan/scan.go) lines 100 and 107.** Both currently pass the literal `"unterminated quote"`. Replace with `"unterminated string literal — check for a missing '\"'"` (the inner `"` is backslash-escaped per Go string literal rules). Both sites get the *same* message text — the user-visible distinction between "ran to newline" and "ran to EOF" is not actionable, and one message string is one thing to grep.

- **Leave [`internal/scan/scan.go:126`](../../internal/scan/scan.go#L126) (`unterminated number literal`), [`internal/scan/scan.go:147`](../../internal/scan/scan.go#L147) (`unterminated block comment`), and [`internal/scan/scan.go:187`](../../internal/scan/scan.go#L187) (`unknown byte %b`) untouched.** Out of scope — each is a separate UX surface with its own rewording question, and the M17.2 memo names only the unterminated-quote text.

- **Update any test pinning the literal old string.** Grep `grep -rn 'unterminated quote'` from repo root before the edit; every match outside [`internal/scan/scan.go`](../../internal/scan/scan.go) — likely in [`internal/scan/scan_test.go`](../../internal/scan/scan_test.go), possibly in [`internal/parse/parse_test.go`](../../internal/parse/parse_test.go), [`internal/lint/`](../../internal/lint/), or `testdata/` golden expectations — gets the new text. If a fixture file contains the old text as a comment, leave it (comments are documentation, not assertions).

- **Add a regression test in [`internal/scan/scan_test.go`](../../internal/scan/scan_test.go):** `TestM17_5_UnterminatedQuoteMessage`. Two sub-cases — input `"abc\n` (newline-terminated) and input `"abc` at EOF (EOF-terminated). Both must produce exactly one `Codes.SCAN` diagnostic whose `Message` is the literal string `unterminated string literal — check for a missing '"'`.
