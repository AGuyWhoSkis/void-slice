# M7.1.1 · Extend diagnostic cap to scan output

**Status:** todo
**Goal:** M7
**Size:** small
**Origin:** M7.1

## What

[M7.1](../in-progress/) capped parse + validate diagnostics, plumbed through `parse.Opts` and `lint.Options.MaxDiagnostics`. Scan (lex) diagnostics are not on the cap path: in [internal/lint/lint.go](../../internal/lint/lint.go), `scanDiags` are appended to the output before `validateDiags`, so a pathological body that produces hundreds of thousands of scan errors can blow past the 10 000-diagnostic cap inside the Worker isolate. M7.1's ticket Scope point 3 said the cap should cover "lex diagnostics, structural diagnostics, `VALIDATE_*` warnings" — the lex coverage was deferred during M7.1 implementation because the M7 goal text named `internal/parse/` specifically. M7.1.1 closes that gap.

## Scope

What must end up true:

- `lint.Lint` applies a single combined cap to the merged `scanDiags + validateDiags` output before returning, when `Options.MaxDiagnostics > 0`. The cap value flows from `Options.MaxDiagnostics` exactly as today.
- When the combined output would exceed the cap, the final entry is replaced with a sentinel carrying `parse.Codes.DIAGNOSTICS_TRUNCATED` and the same message shape M7.1 already uses.
- The cap inside `parse` / `validate` stays in place (defense in depth; cheap). M7.1.1 adds the lint-level enforcement on top.
- A `lint_test.go` test covers the new path: a fixture that produces only-scan diagnostics in excess of a low cap, confirms truncation kicks in at the lint layer.
- Default callers (CLI, LSP, server) remain uncapped — `lint.New()` unchanged.
- No regression in existing tests; the cap value the Worker uses (10 000) is unchanged.

Out of scope: capping scan emissions inside `internal/scan/` itself. The lint-level cap is the natural single seam; pushing into scan would reshape `Scan`'s API for marginal benefit.

## Dependencies

[M7.1](../in-progress/) (or wherever the diagnostic-count cap ticket lives at the time of pickup).

## Verification

- `go test ./...` passes including the new `lint_test.go` case.
- Hand-construct a pathological input that triggers many scan errors; confirm `lint.NewWithOptions(lint.Options{MaxDiagnostics: 5}).Lint(...)` returns exactly 5 diagnostics ending with the sentinel.
- Same input through `lint.New().Lint(...)` (uncapped) returns the full unbounded set.
