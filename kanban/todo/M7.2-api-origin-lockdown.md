# M7.2 · API origin lockdown

**Status:** todo
**Goal:** M7
**Size:** small-to-medium

## What

The Worker currently sets `Access-Control-Allow-Origin: *` ([worker/index.js:38-47](../../worker/index.js#L38-L47)) because [wrangler.toml:8](../../wrangler.toml#L8) hard-codes `ALLOWED_ORIGIN = "*"`. Any origin can call `/lint`, including foreign sites that wish to spend this account's rate-limit budget. M7.2 narrows the allowlist to the front-ends that actually need the API: the production Pages domain and per-PR preview Pages domains (`pr-<N>.voidslice.pages.dev`).

## Scope

What must end up true:

- The Worker accepts CORS requests only from origins on a documented allowlist. Origins not on the allowlist receive responses with no `Access-Control-Allow-Origin` header (browsers will then block the response).
- The allowlist covers, at minimum: the production Pages origin and the preview pattern `pr-<N>.voidslice.pages.dev` (matched by exact host suffix or equivalent — not by regex on user-supplied data).
- Configuration lives in `wrangler.toml` (and/or environment-variable inputs), not hard-coded in `worker/index.js`. A reader can change the prod origin without editing JS.
- `OPTIONS` preflight responses also gate on the allowlist — denied origins get a non-CORS response, not a 204 with permissive headers.
- The `Vary: Origin` header is set whenever `ACAO` is set (already true in the existing code; preserve when refactoring).
- `/health` either stays public (no CORS gate) or is documented as also gated — pick one and stick with it.
- Existing rate-limit / body-size / content-type behavior is untouched — this ticket changes only origin policy.

Out of scope: token-based auth, IP allowlisting, custom domains for the Worker itself. The `RATE_LIMITER` namespace stays as-is.

## Dependencies

None.

## Verification

- `wrangler dev worker/index.js` locally; `curl -i -X OPTIONS -H "Origin: https://voidslice.pages.dev" -H "Access-Control-Request-Method: POST" http://localhost:8787/lint` → response includes `Access-Control-Allow-Origin: https://voidslice.pages.dev` (or matching prod origin) and `Vary: Origin`.
- Same curl with `-H "Origin: https://evil.example"` → no `Access-Control-Allow-Origin` header.
- Same curl with `-H "Origin: https://pr-42.voidslice.pages.dev"` → allowed.
- After preview deploy, an actual browser load of the preview Pages origin successfully calls `/lint` (no CORS console errors); a fetch from an unrelated origin in DevTools is blocked.
- `go test ./...` passes — covers the harness layers that exercise the Worker in unit tests.
