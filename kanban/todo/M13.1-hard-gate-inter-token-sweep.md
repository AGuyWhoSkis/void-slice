# M13.1 · Hard-gate the inter-token-gap lexinvariance sweep

**Status:** todo
**Goal:** M13
**Size:** small

## What

Flip the lexinvariance harness from "report-only triage tool" to "hard CI
gate" for the three inter-token-gap transforms. Add a Go test (no build tag)
that walks `testdata/golden/`, runs the existing `lexinvariance.Scan`, and
fails when any in-scope transform yields a finding. This is the assertion-
shape half of M13 — the surface-and-fix half follows in M13.2 (docs) and any
follow-up tickets filed against findings the gate surfaces.

**In-scope transforms** ("hard-gate kinds"): `TransformReindent`,
`TransformTabSpace`, `TransformInterTokenPadding`. These mutate whitespace
bytes within or adjacent to inter-token gaps and must not affect the
diagnostic-code multiset.

**Out-of-scope transforms** (stay report-only via the existing build-tagged
sweep): `TransformBlankLineJitter`. Goal explicitly parks newline mutation as
a separate invariant.

**Corpus scope:** `testdata/golden/` only. `testdata/cascades/` is
intentionally broken; its lexinvariance pin already lives in
`TestKnownCaseV1V2Converges` and is unchanged by this ticket.

## Scope

- `internal/harness/lexinvariance/lexinvariance.go` — add a hard-gate
  predicate on `TransformKind`. Literal shape:

  ```go
  // IsHardGate reports whether this transform mutates inter-token-gap
  // bytes that, per M13's invariant, must not affect the diagnostic-code
  // multiset. True for Reindent, TabSpace, and InterTokenPadding; false
  // for BlankLineJitter (newline mutation, parked as a separate invariant).
  func (k TransformKind) IsHardGate() bool {
  	switch k {
  	case TransformReindent, TransformTabSpace, TransformInterTokenPadding:
  		return true
  	}
  	return false
  }
  ```

  Also update the package doc comment: the "prospecting tool … files no
  fixes" framing is now mixed — gate kinds are a hard property, the
  remainder are still triage. Reword to reflect the split.

- `internal/harness/lexinvariance/lexinvariance_gate_test.go` — **new file,
  no build tag**, `package lexinvariance_test`. Defines
  `TestLexinvarianceHardGate`:

  1. Walk `testdata/golden/` (single root — not cascades). Use the same
     `lintableExt` filter the build-tagged sweep uses (`.decl`,
     `.entitydef`, `.entities`, `.cfg`; skip `.decl.xml`).
  2. For each file: baseline lint, then `lexinvariance.Scan`.
  3. For each returned finding where `f.Transform.IsHardGate()` is true,
     `t.Errorf` with `path`, kind, variant, and `CodeDiff` so a CI failure
     names the breaking file and transform on first read.
  4. No file writes. The report under `lexinvariance-report.md` remains the
     build-tagged sweep's responsibility.

  Re-use `convertLintDiags` from `lexinvariance_unit_test.go` (same
  `_test` package, both files compile under the default test build).

- `Makefile` — update the `lexinvariance` target's help line so it reads:
  "run the M12.15 report-writing sweep (BlankLineJitter + triage; the
  inter-token-gap gate runs under `go test ./...`)". One line in the
  `help:` block, one line in the comment above the `lexinvariance:` recipe.

## Format example

Expected new test failure shape (when a finding exists):

```
--- FAIL: TestLexinvarianceHardGate (X.XXs)
    lexinvariance_gate_test.go:NN: hard-gate finding: testdata/golden/<path>
        transform=reindent variant=1
        diff=+VOID_SCAN ×3, -VALIDATE_FOO
```

## Dependencies

None.

## Verification

- `go test ./internal/harness/lexinvariance/` passes with the new gate test
  green on the current corpus (sweep is at 0 findings as of 2026-05-12 per
  the M12.18 closure).
- `go test -tags=lexinvariance ./internal/harness/lexinvariance/` still
  passes; the build-tagged sweep and `TestKnownCaseV1V2Converges` are
  unaffected.
- `grep -n "IsHardGate" internal/harness/lexinvariance/lexinvariance.go`
  returns the new method.
- `ls internal/harness/lexinvariance/lexinvariance_gate_test.go` exists and
  has no `//go:build` directive.
- A red gate must escalate, not silently relax: if the gate is red on first
  run, file follow-up M13.x tickets pinning each finding (engine-fix or
  input-boundary-router per M12.16/17/18 precedent) and surface to the user
  before merging the gate. **Do not** edit the gate's corpus scope, the
  `IsHardGate` set, or add a skip list to make it green — those are
  explicit non-options per the goal.

## Out of scope (intentionally deferred)

- **Documenting the new contract.** CLAUDE.md updates live in M13.2.
- **BlankLineJitter as a hard gate.** Goal scope explicitly parks newline
  mutation as a separate invariant; the build-tagged sweep still surfaces
  BlankLineJitter findings for triage but the new gate ignores them.
- **`testdata/cascades/` under the gate.** Cascades are intentionally
  broken; their pin lives in `TestKnownCaseV1V2Converges`. Bringing them
  under the gate would conflate cascade-detection correctness with
  whitespace invariance.
- **Wiring `make lexinvariance` into `make harnesses`.** The aggregate is
  for cross-runtime harnesses (Node + npm); the new gate is pure Go and
  rides `go test ./...`. The build-tagged report-writing sweep stays opt-in.
- **Fixing any findings the gate surfaces.** Each finding gets its own
  follow-up ticket (M13.x) per the goal's "fix-or-router, never skip"
  contract.
