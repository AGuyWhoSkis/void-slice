# M4.9 · Report-layer golden rendering coverage for corpus diagnostics

**Status:** todo
**Goal:** M4
**Size:** small

## What

The renderer in [internal/report/](../../internal/report/) produces both pretty (carets) and JSON outputs. Today its golden tests pin a curated handful of diagnostic shapes; M4.3–M4.7 may emit new diagnostic codes (e.g. the malformed-XML code chosen in M4.7) and will certainly cause existing codes to emerge from new shape contexts. This ticket extends the report-package golden suite so every M4-touched diagnostic code has its pretty + JSON rendering pinned on a representative corpus diagnostic.

This is the **report-layer golden coverage** ticket.

## Scope

- Inventory the diagnostic codes M4.2's final-state allowlist + corpus actually emits (post-M4.3–M4.8). For each, ensure the report-package golden suite has at least one pretty + JSON render fixture.
- Use representative diagnostics drawn from the corpus where possible (so the goldens reflect real source spans, not synthetic line/column).
- Renderer changes only if the corpus surfaces a rendering bug (e.g. caret math on long lines, multi-byte UTF-8 in source). Otherwise this is purely test-coverage work.

## Dependencies

M4.3–M4.7 (the diagnostic code surface needs to stabilize first). Can land in parallel with M4.10.

## Verification

- New / extended `internal/report/` golden tests covering pretty + JSON output for each M4-relevant diagnostic code. **Report-layer golden coverage.**
- `go test ./internal/report/...` green; `go test ./...` green.
