# M12.11 · Tighten the discovery harness Silent signal

**Status:** todo
**Goal:** M12
**Size:** small
**Origin:** M12.9

## What

M12.9's first corpus sweep produced **18,543 Silent (`no-op-mutation`)
findings** against ~270 K mutations. Spot-checking the spot-checked
`d2/game1/` goldens shows two distinct shapes:

1. **True signal.** Deleting `=` between an identifier and a `{` value
   (`edit = { … }` → `edit { … }`) leaves the diag set unchanged because
   the parser permissively reads the result as a typed-block. That's
   a real "linter missed a structural change" finding — exactly what
   Silent is supposed to surface.
2. **Noise.** Inserting `}`, `;`, `=`, etc. at gap-start positions
   often lands somewhere the grammar already tolerates (mid-comment
   gap, between top-level statements). The mutated bytes parse to a
   different but equally-valid program, so the diag set is identical.
   The signal is honest but uninteresting — these aren't cascades the
   parser missed; they're alternate-but-valid grammar reads.

Of ~18 K Silent findings, the majority appear to be shape (2). Sifting
the ~few hundred shape-(1) findings out of that pile is what makes the
human-triage step expensive.

## Scope

- Add a new `Options.SilentMode` enum (or analogous bool) to
  [`internal/harness/discovery/discovery.go`](../../internal/harness/discovery/discovery.go):
  - `SilentAll` — current behavior.
  - `SilentDeletesOnly` (default) — fire Silent only when
    `m.Kind == MutationDelete`. Inserts that produce no diag change
    almost certainly hit case (2) above.
- Optional secondary filter: drop Silent when the mutation site is in
  a token-gap that the parser already treats as separator-equivalent
  (e.g. whitespace gap between two top-level statements). Implementing
  this cleanly would need a small `parse`-layer query — keep behind a
  feature flag if it lands in this ticket.
- Re-run the harness; compare counts before/after. Target: ≥ 80 %
  reduction in Silent findings, with the spot-checked deletes-`=`
  findings on `d2/game1` still surfaced.

## Dependencies

M12.9 (closed — harness must exist).

## Verification

- `go test -tags=discovery ./internal/harness/discovery/` clean.
- New unit test in
  [`internal/harness/discovery/discovery_test.go`](../../internal/harness/discovery/discovery_test.go)
  (the build-tagged file already has setup) pins the deletes-only
  behavior on a synthetic 2-statement fixture: insert `;` between
  statements doesn't fire Silent, delete `=` mid-statement does.
- The corpus-sweep `discovery-report.md` Silent count drops markedly
  while still listing the `ident { … }` shape findings on
  `d2/game1/`.

## Out of scope

- Distinguishing shape-(1) from shape-(2) by static-analyzing the
  mutated bytes against the parser's lookahead tables. Too coupled to
  parser internals; the deletes-only heuristic is the 80/20.
- Reworking Spike or Blowup thresholds. M12.9 baked sensible defaults
  (K=5, W=2); tighten only if a separate triage pass calls for it.
