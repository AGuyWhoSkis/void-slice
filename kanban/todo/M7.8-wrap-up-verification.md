# M7.8 · Wrap-up: manual verification + goal close

**Status:** todo
**Goal:** M7
**Size:** small

## What

M7 ships a security and robustness pass across the Worker, the Pages site, and the deploy pipeline. Most verification is automated (`go test`, harnesses, CI), but several items have a manual step that lives outside CI: browser-side CSP-violation checks, real-domain CORS exchanges, the rollback drill, the durable-log retrieval recipe. M7.8 collects those manual steps into one place, runs the matrix once against the M7 integration preview, and writes the M7 retrospective into the goal file.

## Scope

What must end up true:

- A consolidated manual-verification document exists (e.g. `kanban/goals/M7-verification.md`, or appended as a section to `kanban/goals/M7.md` — implementer's call). It lists, for each of M7.1–M7.7, the manual steps a reviewer should run and the expected outcome.
- The document distinguishes **local steps** (commands a developer can run on their machine: `go test`, `wrangler dev`, `wrangler pages dev`) from **preview/prod steps** (curls against a real preview URL, browser-side checks, the rollback drill). Each item is labeled.
- At minimum, the document captures:
  - **M7.1**: fully automated by `go test ./...`; no manual step.
  - **M7.2**: local `wrangler dev` curls with allowed/denied `Origin:` headers; preview-time browser load that confirms the prod and `pr-<N>` Pages origins exchange CORS preflight cleanly and unrelated origins are blocked.
  - **M7.3**: local `wrangler pages dev` + `curl -I` to confirm headers are present; preview-time browser load with DevTools open, confirming zero CSP violations on a full lint round-trip.
  - **M7.4**: smoke-script unit checks are local; the rollback drill is preview/prod-only and documented as a one-off scratch-PR exercise to run once before final merge.
  - **M7.5**: local `wrangler dev` cache hit/miss curls; preview-time same curls against the preview Worker URL plus a rate-limit interaction check.
  - **M7.6**: local invocation of the staleness-check script; CI step shows green at PR review.
  - **M7.7**: cannot be exercised locally — preview/prod-only. Steps: hit the prod Worker, wait for the platform's flush window, confirm log lines arrive in the configured R2 destination via a documented `wrangler r2` (or equivalent) retrieval command.
- The matrix is run end-to-end once against the M7 integration preview. Any failure or regression is fixed before the goal closes — either by amending the relevant earlier ticket's PR (if still open) or by a follow-up PR that names the fix.
- Once the matrix is green, the M7 goal file gets a `## Retrospective` section appended (matching the shape used by closed goals like [M6](../../kanban/goals/M6.md), [M8](../../kanban/goals/M8.md)), the `**Status:**` field flips from `planned` to `done`, and tickets M7.1–M7.7 are removed from `kanban/todo/` (or `kanban/in-progress/`) via `git rm`.
- The retrospective covers, at minimum: what shipped (one bullet per ticket), anything worth remembering for future Cloudflare/security work, and any deferred items that should seed the next goal.

Out of scope: documenting individual ticket details (those live in the closed PRs and `git log`); writing per-deliverable runbooks beyond the manual-verification doc.
