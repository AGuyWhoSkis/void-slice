# M9.3 · Per-goal branch convention; retire `m<N>-dev`

**Status:** todo
**Goal:** M9
**Size:** medium

## What

Replace shared `m<N>-dev` integration branches with per-goal branches (`goal/M<N>-<slug>` or equivalent — exact name decided at implementation time). Tickets target the goal branch; the goal branch is the unit that lands to `main`. Slash commands, prose, and any scripts that reference the old shared-branch flow are removed entirely so the old model is unreachable — zero-tolerance, since lingering fragments invite misuse.

## Scope

- Per-goal branch naming convention defined and documented in `kanban/README.md` lifecycle section
- `CLAUDE.md` includes the merge-to-main protocol (push and stop; the human merges)
- `/implement-ticket` updated to target the goal branch instead of `m<N>-dev`
- All references to `m<N>-dev` and the shared-branch flow purged from living slash commands, `CLAUDE.md`, scripts, and Makefile
- Any command, script, or config dedicated solely to the old flow is deleted, not just edited

## Dependencies

None — independent of M9.1/M9.2.

## Verification

`grep -ri 'm<N>-dev\|m[0-9]\+-dev'` across tracked files returns no living references (only historical mentions in `git log` / closed retros are acceptable). `/implement-ticket` documentation describes the per-goal-branch flow. `CLAUDE.md` states the merge protocol.
