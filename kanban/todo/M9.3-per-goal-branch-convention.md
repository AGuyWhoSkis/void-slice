# M9.3 · Per-goal branch convention; retire `m<N>-dev`

**Status:** todo
**Goal:** M9
**Size:** medium

## What

Replace shared `m<N>-dev` integration branches with per-goal branches. Tickets target the goal branch; the goal branch lands to `main` as a single human-reviewed PR when the goal closes. Living references to the retired flow are deleted, not edited around — the old shared-branch model becomes mechanically unreachable so it can't be misused.

## Scope

- **Branch naming.** `goal/M<N>-<slug>`. The slug is the goal file's title, lowercased and hyphenated (e.g. M9 "Concurrent agent workflow" → `goal/M9-concurrent-agent-workflow`). The slug rule is documented so `/goal-dispatch` (M9.4) can reproduce it deterministically.

- **Convention documented in `kanban/README.md` lifecycle section.** New paragraph or subsection covering: branch name, created from `main` (manually or by `/goal-dispatch`), tickets commit onto it, single PR per goal opened against `main`, PR merged by human when goal closes.

- **`/implement-ticket` rewrite (step 4).** Replace the `m<N>-dev` checkout/create logic with: assert the working tree is on the goal branch (`goal/M<N>-*`); if not, fail and tell the user to switch via `/goal-dispatch` or `git checkout`. Do *not* auto-create the goal branch — branch creation is `/goal-dispatch`'s job, not `/implement-ticket`'s. The trailing paragraph that explains the integration-branch model is rewritten to describe the per-goal convention.

- **`/goal-slice` handoff message fixed.** Line 19's "Commit them on the per-goal integration branch (`m<N>-dev`, branched from `main` if it doesn't exist)" becomes "Commit them on the goal branch (`goal/M<N>-<slug>`, created via `/goal-dispatch` if it doesn't exist)."

- **`CLAUDE.md` merge protocol added.** One short paragraph: merges to `main` require human approval and green CI; push the goal branch and stop; the human merges. Informational, not prohibitive — the protection (M9.5) enforces, the prose orients.

- **`.claude/plans/parallel-agents.md` deleted.** The planning scaffold has been superseded by `kanban/goals/M9.md` and the M9.* tickets. Deleting it removes the last "live" prose reference to `m<N>-dev` and prevents the agent from reading retired planning as current direction.

- **Verification grep is clean.** `grep -rn 'm<N>-dev\|m[0-9]\+-dev'` across tracked files returns zero hits, except (a) the M9 goal file (which describes the retired model as the *problem* M9 solves) and (b) `git log` history. The `kanban/todo/M9.3-*` ticket file gets deleted on ticket close, so no exception needed for it.
