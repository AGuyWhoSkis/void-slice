# M4.1 — `.decl` format taxonomy & dispatch decision

**Status:** todo

Planning ticket. The 64 promoted intake files under [testdata/corpus-mini/intake/](../../testdata/corpus-mini/intake/) plus the 5 existing `.decl` files under `corpus-mini/{d2,doto}/game1/` contain at least four distinct top-level grammars sharing the `.decl` extension, plus a Void Explorer XML sidecar variant (`.decl.xml`). Before any grammar work begins, we need a written taxonomy and a dispatch decision that future grammar tickets cite.

## Inputs

- `testdata/corpus-mini/intake/` — 64 files, all golden, all `.decl` or `.decl.xml`.
- `testdata/corpus-mini/{d2,doto}/game1/` — 5 existing golden `.decl` files + 1 `.entities`.
- Initial corpus walk (recorded for context, not authoritative — taxonomy ticket re-derives):
  - **Shape 1 — curly inherit/edit**: `{ inherit = "..."; edit = { ... } }`, `=` and `;` separated. Sub-types include `arktree`, `cpntplayer*`, `entitydef`, `fx`, `kiscule`, `mapinfo`, `midnightscene`, `particledt`, `rulehandler`, `localized.*.speechbarks`, `localized.*.speechscene`. ~40 of 64.
  - **Shape 2 — animset**: whitespace-separated, no `=`, no `;`. `previewmd6 "..."`, nested `groups { ... }`, `aliases { group 0 alias { ... } }`. 7 of 64.
  - **Shape 3 — material**: tab-aligned key-value, no `=`, no `;`. `m_PhysicsMaterial "..."`, top-level `version 5`, `state { }`, `options { ... }`. 3 of 64.
  - **Shape 4 — renderprog**: `newstyle`, `state { ... }`, `hlsl_prefix { ... }` with embedded HLSL preprocessor + source. 2 of 64. **Out of scope per goal (G-C).**
  - **Sidecar — `.decl.xml`**: `<ResourceInfo name="..." classname="..." />`. Void Explorer export/import metadata, not game artifacts. 12 of 64.

## Deliverables

1. **Taxonomy doc.** Inventory every file in the golden corpus by shape. Append a section to [kanban/goals/M4.md](M4.md) (or a sibling doc if it bloats the goal) listing each shape with: a one-line grammar description, a representative example file, and the count.
2. **Dispatch decision.** Pick one of:
   - **(a) Extension-based**: `.decl.xml` → XML handler; `.decl` → content-sniff among shapes 1–3.
   - **(b) Filename-infix-based**: parse `..animset..` / `..material..` / etc. from filename to route. Risky — relies on file-naming convention, not content.
   - **(c) Content-sniff**: peek the first non-whitespace token. `<` → XML, `{` → shape 1, identifier-then-quote (`previewmd6 "..."`) → shape 2 or 3, `newstyle` → shape 4. Most robust; doesn't depend on filename.
   - **(d) Hybrid**: extension picks XML vs not; content-sniff picks among shapes 1–4.
   
   Document the decision and why in the goal file. Default lean is **(d)**: cheap, robust, doesn't hardcode filename conventions.
3. **Allowlist inventory** for the M4.2 harness. List the diagnostic codes currently firing on golden corpus, with counts, so M4.2's allowlist starts in the right shape. Today's count: 749,570 `PARSE_UNEXPECTED_TOKEN`, 2,786 `VOID_SCAN`, 329 `PARSE_EXPECTED_SYMBOL`, 1 `PARSE_EXPECTED_SEMICOLON`, plus the existing corpus-mini hits (7 `VALIDATE_ARRAY_COUNT_MISMATCH`, 1 `VALIDATE_ARRAY_MISSING_NUM`, 1 `LINT_VE_INCONSISTENCY`).
4. **Game-subdir question.** Decide whether to leave the 64 files flat under `corpus-mini/intake/`, redistribute into `d2/game1/` + `doto/game1/` based on filename heuristics, or keep `intake/` as a permanent third subpath. Affects `internal/scan/scan_test.go`'s `goldenFileNames` list only if any of the 64 graduate into spot-checked goldens.

## Done when

- A dispatch strategy is named and defended in one paragraph.
- The allowlist inventory is concrete enough that M4.2 can be opened against it without re-running corpus analysis.
