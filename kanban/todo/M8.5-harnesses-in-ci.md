# M8.5 · Run harnesses in CI

**Status:** todo
**Goal:** M8
**Size:** small
**Origin:** M8.2

## What

Wire `make harnesses` into [.github/workflows/ci.yml](../../.github/workflows/ci.yml)
so the M8.1 (WASM-boundary) and M8.2 (Worker-glue) harnesses run on every PR
and push. Without CI enforcement they rot — a future change to
`worker/index.js`, `cmd/voidslice-wasm/main.go`, or `internal/report` can
break them silently because nobody runs them locally on every change.

## Scope

What must end up true:

- A CI job (or step inside an existing job) runs `make harnesses` after
  setting up Go and Node.
- Node version is pinned (Miniflare 3 needs ≥18; the harness was developed
  on Node 20). Bumping to Node 22 unlocks Miniflare 4 — pick one and pin.
- `npm ci` runs before the harness step (so `worker-harness`'s
  `node_modules` dep resolves cleanly).
- The job fails the build on any harness failure.
- Caching: `node_modules` cache keyed on `package-lock.json` to keep the
  harness step fast.
- README / CLAUDE.md (if either documents the test surface) is updated to
  list `make harnesses` alongside `go test ./...` as a CI gate.

Out of scope: parallelizing harnesses with the Go test job (start with one
sequential job; optimize later if it becomes the long pole).

## Dependencies

- M8.1 (landed, on M8 integration branch).
- M8.2 (this ticket's origin; landed on M8 integration branch).
- M8.3 may add its own harness invocation; if it lands first, fold its
  command into the same CI step.

## Verification

- Open a PR that intentionally breaks one Worker case (e.g. revert
  `Vary: Origin`); CI fails with the expected localized message.
- Revert the break; CI passes.
- The harness step runs in under 60s on a clean cache miss (Miniflare boot
  + 4 instance families is the dominant cost).
