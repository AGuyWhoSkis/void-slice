# M7.3 · Static-asset hardening headers

**Status:** todo
**Goal:** M7
**Size:** small

## What

Pages currently serves the playground SPA with whatever default response headers Cloudflare chooses — no Content-Security-Policy, no Referrer-Policy, no X-Content-Type-Options, no X-Frame-Options. M7.3 adds a `web/public/_headers` file (a Cloudflare Pages config) that sets a sensible security baseline on every served asset, with a CSP tight enough that an injected script can't exfil to an arbitrary host but loose enough that the SPA's own bundle and the Worker API continue to load.

## Scope

What must end up true:

- A new file `web/public/_headers` is created (Vite copies `public/` into `dist/` verbatim, where Pages reads `_headers`).
- The headers file sets, on HTML responses (and on the fallback / matching all paths as appropriate):
  - `Content-Security-Policy`: `default-src 'self'`, with `connect-src` allowing the Worker origin (prod + preview), `script-src` and `style-src` permitting the bundled assets, `frame-ancestors 'none'`. No `unsafe-inline` / `unsafe-eval` unless the SPA actually requires them — verify by loading the page after the policy lands.
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY` (belt-and-braces alongside `frame-ancestors 'none'`)
  - `Permissions-Policy` denying APIs the SPA does not use (camera, microphone, geolocation, payment, usb, etc. — the standard "deny-most" baseline).
- The CSP's `connect-src` matches the same set of origins the Worker's allowlist permits in M7.2 — keep these in sync.
- The headers apply to both prod Pages and per-PR preview Pages without per-deploy edits.

Out of scope: Subresource Integrity hashes on script tags, HSTS (Cloudflare manages this at the zone level), CSP reporting endpoints. These are larger separately-scoped concerns.

## Dependencies

Coordinate the `connect-src` value with M7.2's allowlist when both land. If M7.2 lands first, mirror its values; if M7.3 lands first, leave a comment in `_headers` flagging the dependency.

## Verification

- `npm run build && npx wrangler pages dev web/dist`; `curl -I http://localhost:8788/` returns all six security headers with expected values.
- After preview deploy: `curl -I https://pr-<N>.voidslice.pages.dev/` returns the same headers; load the playground in a browser, open DevTools, exercise a lint round-trip — zero CSP violation messages in the console.
- `web/dist/_headers` is present in the build output (Vite's `publicDir` should copy it; if not, fall back to placing it in a location Pages reads).
