# M9.7 · `/goal-slice` produces contract-grade tickets

**Status:** todo
**Goal:** M9
**Size:** medium

## What

Update `/goal-slice` (and the underlying ticket-format spec in `/crud-ticket`) so sliced tickets are unambiguous contracts ready for unsupervised agent dispatch — not sketches that defer design to implementation. Codifies the pattern demonstrated in the manual disambiguation pass on M9.1–M9.6: surface decisions, make the call, bake them into the ticket. The current "defer work to implementation time" default is correct for human-driven coding but load-bearing wrong for M9's "agent ships green PR without babysitting" success criterion.

## Scope

- **`.claude/commands/goal-slice.md` rewritten.** The "Defer work to implementation time" rule is replaced with a "Bake in human decisions before dispatch" rule. New text covers:
  - **Principle.** Each ticket is a contract. File paths, format choices, edge-case handling, library choices that affect the contract — all decided before the ticket is written. Deferrals are explicit and reasoned, not implicit.
  - **Conversation flow.** After the title draft, run a per-ticket disambiguation pass: enumerate open decisions, propose answers with reasoning, ask the user only when input genuinely matters. Catch cross-ticket seam violations (two tickets editing the same file in incompatible ways) before writing.
  - **What "contract-grade" looks like.** Concrete file paths in Scope. Format examples in code blocks. Verification steps that are mechanically checkable, not aspirational. Out-of-scope deferrals named with reasoning.
  - **Calibration on questions.** Recommend with reasoning by default; only ask when there's a real fork that affects the user's downstream work. Hedging questions ("where should this live?" with an obvious recommendation) erode the user's time.

- **`.claude/commands/crud-ticket.md` CREATE format updated.** Add a new section to the ticket template:

  ```
  ## Out of scope (intentionally deferred)
  <bullet list of decisions or work considered and explicitly deferred, with reasoning>
  ```

  Placed after `## Verification`. Documents what an implementer should *not* re-litigate.

- **The PROPOSE shape inherits the new section** by virtue of being "same as CREATE with two deltas."

- **Examples in the rewritten `/goal-slice`** point at the M9.1–M9.6 ticket files as exemplars. (The files exist in `kanban/todo/M9.*` at the time M9.7 ships; they're the reference material.)

- **No CLAUDE.md changes.** M9.3 owns CLAUDE.md edits in this goal; M9.7's pattern is captured in the slash-command files.

## Dependencies

None. M9.1–M9.6's *definitions* are the reference material and they already exist; their *implementations* are not required.

## Verification

- `.claude/commands/goal-slice.md` no longer contains the "Defer work to implementation time" rule. The replacement principle is named.
- `.claude/commands/goal-slice.md` describes the per-ticket disambiguation pass and the seam-violation check.
- `.claude/commands/crud-ticket.md` CREATE format includes the `## Out of scope (intentionally deferred)` section.
- A re-read of M9.1–M9.6 confirms they conform to the new format (they should — they're the reference).
- Slicing a hypothetical new goal under the updated `/goal-slice` produces tickets with the new section populated, not blank.

## Out of scope (intentionally deferred)

- Retrofitting closed tickets with the new format — they're closed, `git log` is the closure record.
- Retrofitting open tickets outside M9 (e.g. `G-B.1-inheritance-aware-array-validation.md`) — that ticket predates the new convention and will get the new shape if/when it's reworked.
- Tooling to lint tickets for contract-grade-ness (e.g. "verification section contains an executable check") — separate concern; manual review is fine at this scale.
- Changes to `/implement-ticket` to consume the new section (e.g. surface "Out of scope" deferrals during PLAN) — defensible follow-up, not blocking.
