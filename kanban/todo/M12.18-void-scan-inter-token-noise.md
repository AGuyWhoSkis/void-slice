# M12.18 · VOID_SCAN sensitivity to inter-token whitespace

**Status:** todo
**Goal:** M12
**Size:** medium
**Origin:** M12.15 — F1/F2 in `lexinvariance-report.md`

## What

Two corpus files emit 148 and 116 `VOID_SCAN "unknown byte"` diagnostics
respectively:

- `testdata/golden/generated.decls.renderprog.tlf.gatherdepthminmax.decl`
- `testdata/golden/generated.decls.renderprog.arksssblur.decl`

Both are HLSL-flavored shader files masquerading as `.decl` — they
contain `#include`, `<…>`, preprocessor directives, etc. The scanner
emits one VOID_SCAN per byte it can't classify. Those bytes live
*entirely* in inter-token gaps (e.g. the `#` of `#define`, the angle
brackets of `<tlf/common>`) — nothing carries them into the parser's
token stream.

The M12.15 harness collapses those gaps via `TransformInterTokenPadding`
variant 0 and the count drops to 0. The post-collapse token stream is
identical to the pre-collapse stream (whitespace and comments filtered).
148 → 0 diagnostics with no token change is the canonical invariance
violation.

This raises a design question:

- **Option A — classify these files as non-grammar.** `.decl` files
  generated from shader sources are noise; have `internal/lint`
  recognize the shader-prefix shape and skip-lint them the same way
  binary `.bwm` and `.decl.xml` files are skipped. The lexinvariance
  harness's other findings would then come from grammar-only files.
- **Option B — suppress VOID_SCAN for non-structural unknown bytes.**
  Treat "unknown byte in inter-token position" as informational, not
  diagnostic. The byte was already discarded from the parser's view;
  emitting a per-byte diagnostic for it leaks scanner internals.
- **Option C — leave it.** The diags are accurate ("byte X is unknown
  to the grammar"); the user is meant to clean these files up. Accept
  the axiom violation as known/expected for binary-adjacent inputs.

Pick one in this ticket. Recommend A or B.

## Scope

- Decide A vs B vs C. Document the choice in the ticket close commit.
- Implement the chosen path.
- For A: extend `classifyFile` in `internal/lint/lint.go` (or wherever
  the binary/xml routing lives) with a shader-prefix sniff.
- For B: add a "structural-byte" gate in the scanner's unknown-byte
  emit path. Possibly thread a count threshold — single stray bytes
  in a real grammar file *should* still diag.
- Pin a regression: lint the two shader files; assert the new behavior.
- Re-run `make lexinvariance`: F1/F2 absent.
