# M10.1 · Bootstrap `nits` branch + worktree

**Status:** todo
**Goal:** M10
**Size:** small

## What
Create the storage substrate for nits: a long-lived `nits` branch forked from `origin/main`, a sibling worktree at `../void-slice-nits/`, and a seed file on the nits branch so the directory exists. This ticket ships the bootstrap script only — capture, surface, and adoption flows are downstream tickets.

## Scope
- New `tools/nits-bootstrap.sh`, idempotent, that:
  1. Checks if `nits` branch exists on `origin`. If yes, fetch it. If no, create from `origin/main` and `git push -u origin nits`.
  2. Checks if `../void-slice-nits/` worktree exists. If yes, exit 0 (idempotent). If no, `git worktree add ../void-slice-nits nits`.
  3. If `kanban/nits/` doesn't exist on the `nits` branch, create `kanban/nits/README.md` (one line: `Pending nits live here. See CLAUDE.md § Nits.`), commit, push.
- Bash; uses only `git` and POSIX shell. No new dependencies.
- Re-running prints `nits worktree at ../void-slice-nits` and exits 0.

## Dependencies
None.

## Verification
- `tools/nits-bootstrap.sh` on a fresh checkout creates the branch, worktree, and seed file.
- Re-running `tools/nits-bootstrap.sh` is a no-op (exits 0, no new commits).
- `git -C ../void-slice-nits log --oneline` shows the seed commit on the `nits` branch.
- `git ls-tree origin/nits kanban/nits/README.md` returns a hit.

## Out of scope (intentionally deferred)
- Auto-bootstrap inside `/nit` — the helper (M10.2) errors out with `run tools/nits-bootstrap.sh first` if the worktree is missing. Lazy auto-setup couples M10.1 and M10.2 and hides setup state from the user.
- Tearing down the `nits` branch — the branch is permanent; deletion is not a supported flow.
- Garbage-collecting old claim commits on the `nits` branch — history accumulates monotonically; acceptable at this scale.
