# M8.7 · 500-path coverage in worker-harness

**Status:** todo
**Goal:** M8
**Size:** small
**Origin:** M8.2

## What

[worker/index.js:175-178](../../worker/index.js#L175-L178) wraps the entire
router in a `try/catch` that returns `textResponse(500, "internal error",
env)`. That branch is unreachable from the M8.2 harness today: every
covered case takes a controlled path. If the 500 path stops setting CORS
headers, or starts leaking the error message, nobody finds out until a
production incident exposes the gap.

## Scope

What must end up true:

- One worker-harness case forces `handleLint` (or `ensureWasm`) to throw
  and asserts:
  - status is `500`
  - body is `"internal error"` (no leak of `e.stack` or `e.message`)
  - CORS headers are present and consistent with `ALLOWED_ORIGIN`
- The injection mechanism is light. Options worth considering:
  - Build a Miniflare instance whose `RATE_LIMITER` binding is a wrapped
    binding that throws — this exercises the outer try/catch via
    `env.RATE_LIMITER.limit`.
  - Or: a dedicated Worker variant that imports a thunk that throws,
    pinned to the harness only.
- Keep the case opt-in and self-contained — don't expand the production
  Worker surface for testability.

Out of scope: testing the 500-from-wasm-init path (`ensureWasm` rejects).
That requires swapping the wasm asset — heavier than this ticket.

## Dependencies

- M8.2 (this ticket's origin; landed).

## Verification

- Add the case, run `make worker-harness`, it passes.
- Drop the outer `try/catch` from `worker/index.js`; the case fails with
  `field=status` (the request now propagates as a Miniflare error rather
  than 500). Revert.
- Strip CORS headers from `textResponse`'s 500 path; the case fails with
  `field=header.Access-Control-Allow-Origin`. Revert.
- `go test ./...` and `go vet ./...` pass.
