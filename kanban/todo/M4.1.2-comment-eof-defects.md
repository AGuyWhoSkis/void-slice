# M4.1.2 — Scanner: emit comment tokens at EOF + truncated-comment fixtures

**Status:** todo
**Goal:** M4
**Origin:** M4.1.1

Two latent defects in [internal/scan/scan.go](../../internal/scan/scan.go), surfaced during the M4.1.1 `VOID_SCAN` audit but untouched because they sit outside that ticket's "audit `VOID_SCAN`-emitting branches" scope:

1. **Line comment that reaches EOF without `\n`** ([L139-L152](../../internal/scan/scan.go#L139-L152)) — the inner loop walks to `n` and falls through; no `COMMENT_LINE` token is emitted, no diagnostic. The outer `mainLoop` then resumes from `i+1` and re-tokenizes the comment body as identifiers / numbers / symbols.
2. **Block comment that reaches EOF without `*/`** ([L126-L136](../../internal/scan/scan.go#L126-L136)) — same silent-drop pattern. The outer loop also resumes inside the comment body. Even worse: there's no `VOID_SCAN "unterminated block comment"` diagnostic to mirror the existing `"unterminated quote"` / `"unterminated number literal"` branches.

Both bugs are **latent** — the current `testdata/golden/` corpus has no truncated-comment files, which is why golden tests pass and the M4.1.1 audit didn't surface them. They will fire as soon as a real-world game file is truncated mid-edit, or a user feeds a partial paste into the linter.

## Inputs

- Scanner branches to fix: [scan.go:126-136](../../internal/scan/scan.go#L126-L136) (block) and [scan.go:139-152](../../internal/scan/scan.go#L139-L152) (line).
- Reference shape for emit-on-EOF: the existing `unterminated quote` / `unterminated number literal` branches at [scan.go:97-100](../../internal/scan/scan.go#L97-L100) and [scan.go:117-119](../../internal/scan/scan.go#L117-L119).

## Deliverables

1. **Line-comment EOF fix.** When the inner loop walks to `n` without finding `\n`, emit a `COMMENT_LINE` token spanning `[i, n)` and set `i = n`. No diagnostic — line comments terminating at EOF are valid.
2. **Block-comment EOF fix.** When the inner loop walks to `n` without finding `*/`, emit a `COMMENT_BLOCK` token spanning `[i, n)`, emit a `VOID_SCAN` diagnostic with message `"unterminated block comment"` over the same span, and set `i = n`.
3. **Corpus fixtures.** Add small `.decl` files under `testdata/golden/` (flat root) covering: (a) line comment ending at EOF with no trailing newline, (b) block comment with no closing `*/`, (c) block comment closed normally followed by content (sanity check that the fix doesn't regress the happy path). These feed `internal/lint/`'s clean-sweep / coverage-audit walkers as well as serving as named fixtures for the new scanner unit tests.
4. **Unit tests** in [internal/scan/scan_test.go](../../internal/scan/scan_test.go) for both EOF cases (matching the existing `unterminated-quote` / `unteriminated-number` test pattern).

## Done when

- A `// foo` file with no trailing `\n` produces exactly one `COMMENT_LINE` token spanning the full input, zero diagnostics.
- A `/* foo` file with no closing `*/` produces exactly one `COMMENT_BLOCK` token spanning the full input, plus one `VOID_SCAN "unterminated block comment"` diagnostic over the same span.
- In both cases, the outer `mainLoop` does **not** emit any tokens for content inside the comment body.
- `go test ./...` and `go vet ./...` clean. M4.2's harness (when it lands) tolerates the new fixtures or allowlists their expected diagnostics.

## Notes

- Strictly a scanner-layer ticket. No grammar or validate work.
- The `VOID_SCAN "unterminated block comment"` diagnostic adds a fourth lex-error message alongside `"unterminated quote"`, `"unterminated number literal"`, and `"unknown byte …"`. Mirror their phrasing.
- Fixtures should be tiny (a handful of bytes each) and named to make the truncation explicit, e.g. `eof.line-comment-no-newline.decl`, `eof.block-comment-unterminated.decl`. Keep them at the flat root of `testdata/golden/` — they're not graduated spot-check goldens.
