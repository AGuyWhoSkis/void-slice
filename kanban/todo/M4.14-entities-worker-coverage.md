# M4.14 · sub-1 MiB `.entities` fixture for worker/frontend oracle coverage

**Status:** todo
**Goal:** M4
**Size:** small
**Origin:** M4.12

## What

M4.12 added a `.entities` representative (`corpus-entities`) to the M8.4 differential oracle's fixture list. The only available `.entities` golden — `testdata/golden/d2/game1/maps.campaign.dunwall.escape.tower.dunwall_escape_tower_p.entities` — is 7.7 MB, which exceeds the worker's `MAX_BODY_BYTES = 1 << 20` (1 MiB) cap. The cap is a real production constraint, not a test knob, so the fixture sets `layers: ["native", "wasm"]` and skips the worker + frontend layers. As a result, the oracle has zero `.entities`-shape parity coverage at boundaries 2 (wasm↔worker) and 3 (worker↔frontend).

This is a small but real coverage gap: any `.entities`-specific drift introduced by the worker glue or frontend transport (e.g. encoding handling, header processing) won't be caught by the oracle.

## Scope

- Add a sub-1 MiB `.entities` fixture that exercises the same grammar surface as the existing golden but fits under the worker body cap. Two viable options:
  - Trim an excerpt from the existing 7.7 MB golden (preserve the outer `Version N` + a few representative components).
  - Hand-author a minimal `.entities` sample covering the M1 grammar surface.
- Add it to `worker/harness/fixtures.mjs` with full layer coverage (no `layers` override).
- The 7.7 MB `corpus-entities` fixture stays as-is for native↔wasm coverage.

## Dependencies

M4.12 (introduces the `layers` field and the gap).

## Verification

- `make oracle` shows the new fixture passing through all four layers.
- `make harnesses` green.
