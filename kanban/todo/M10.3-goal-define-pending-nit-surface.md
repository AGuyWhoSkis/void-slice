# M10.3 · `/goal-define` pending-nit surface

**Status:** todo
**Goal:** M10
**Size:** small

## What
Make `/goal-define` aware of pending nits. After the user confirms the goal's `Paths:` and the overlap check runs, list pending nits with their captured Paths and mark which fit within the new goal's Paths. Read-only — adoption is `/goal-slice`'s job.

## Scope
- Edit `.claude/commands/goal-define.md`:
  - Add a new step `### Pending nits` between the §2 overlap check and §3 (status).
  - Step does:
    1. `git fetch origin nits 2>/dev/null` (best-effort; skip cleanly if branch absent).
    2. `git ls-tree -r --name-only origin/nits kanban/nits/` to enumerate.
    3. For each, `git show origin/nits:<path>` and parse `Paths:` block.
    4. Format as a markdown table with columns: `file`, `description` (first heading line of nit), `Paths`, `fits` (✓ if subset of this goal's Paths, ✗ otherwise).
    5. Output: `Pending nits (N):` with the table, or `No pending nits.` when zero.
  - Note in the markdown step: `Surface only — adoption happens at /goal-slice. If a non-fitting nit looks worth adopting, extend this goal's Paths and re-run the overlap check.`
- If the `nits` branch doesn't exist (pre-M10.1, fresh clone): print `(nits substrate not yet bootstrapped — run tools/nits-bootstrap.sh)` and continue without erroring.
- No mutation. No nit-claim push. No worktree changes.

## Dependencies
M10.1.

## Verification
- `/goal-define` on a codebase with the `nits` branch but no nits: prints `No pending nits.`
- `/goal-define` after a `/nit` capture: lists the captured nit with its Paths and ✓/✗ relative to the new goal's Paths.
- `/goal-define` does not modify the `nits` branch (`git -C ../void-slice-nits log --oneline` unchanged before/after).
- On a checkout where the `nits` branch is missing: `/goal-define` prints the `not yet bootstrapped` line and proceeds; doesn't error.

## Out of scope (intentionally deferred)
- Adoption from within `/goal-define` — keeps the seam clean. Goals are an intent artifact; nits attach at slicing time when tickets are being written anyway.
- Filtering by recency or originator — flat listing is fine at this scale.
- Pagination — pending-nit count is bounded by user discipline, not by the system. Long lists self-correct via `/goal-slice` adoption.
