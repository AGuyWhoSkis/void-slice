# M9.5 · Branch protection as code

**Status:** todo
**Goal:** M9
**Size:** small

## What

Move the merge guardrail for `main` out of the GitHub UI into a committed ruleset. Merge to `main` mechanically requires human approval and green required CI checks; the JSON config is the source of truth and survives UI drift. This is the trust anchor that makes the rest of M9 safe to operate — without it, "agent doesn't merge" is a prose promise rather than an enforced invariant.

## Scope

- **Mechanism.** GitHub *ruleset* (not classic branch protection). Exported as JSON to `.github/rulesets/main.json`. Rulesets are GitHub's current config-as-code surface for branch rules.

- **Required status checks** (must pass before merge): `lint`, `build`, `test`, `harnesses`, `preview-deploy`. Names pinned to the existing workflow jobs. `production-deploy` is excluded (it runs on merge, can't be a precondition).

- **Required reviews.** 1 approving review from a non-author. No CODEOWNERS dependency.

- **Block force-push to `main`.** Block branch deletion of `main`.

- **Require linear history.** PRs land via squash or rebase, not merge commits — keeps the terse-subject commit log readable.

- **Bypass actors.** None. Not even the repo owner. Mechanical enforcement is the point.

- **Installation.** Apply once manually via `gh api` (or equivalent) using the committed JSON. Document the apply command in `.github/rulesets/README.md` (one-line: `gh api -X POST repos/:owner/:repo/rulesets --input main.json`). No GitHub Action to auto-apply — config changes ~never; if it drifts, re-apply manually.

- **Documentation.** No `CLAUDE.md` edit — the merge-protocol orientation lives in M9.3. M9.5 is the enforcement; M9.3 is the prose. The committed JSON + `.github/rulesets/README.md` are M9.5's documentation.

## Dependencies

None.

## Verification

- `.github/rulesets/main.json` exists and matches the active ruleset on `origin/main`.
- A test PR cannot be merged into `main` without (a) one approving review from a non-author and (b) all five required checks green.
- Force-push to `main` is rejected by the remote.
- Branch deletion of `main` is rejected by the remote.
- `.github/rulesets/README.md` documents the apply command.

## Out of scope (intentionally deferred)

- CODEOWNERS — useful eventually, separate concern.
- Auto-applying ruleset on JSON change (GitHub Action) — over-engineered for config that rarely changes.
- Protecting goal branches (`goal/M<N>-*`) — those are working branches; protecting them defeats the dispatcher's ability to push to them. Only `main` is protected.
- Branch protection on tags / release branches — no release process exists yet.
