# M12.3 · Fix unterminated-quote cascade

**Status:** todo
**Goal:** M12
**Size:** medium
**Origin:** M12.1

## What

Fix the scanner-layer cascade where a bare `"` consumes downstream bytes as a single string literal until the next `"` or EOF, deceiving the parser about every structural token in between. This is the M11 motivating bug and §2's worst-case shape: blast radius scales to the entire file (up to 16,927 cascade diagnostics across a 33K-line span on `maps.campaign.menu.menu_p.entities` — see [`kanban/goals/M12-cascade-investigation.md`](../goals/M12-cascade-investigation.md) §1 and §2 row 1).

Fix axiom (per M12.md): *a diagnostic should never be wrong.* The post-mutation diagnostic at line N+30K is wrong — that line is valid in the unmutated file and re-validates clean once the quote is closed. After the fix, an unterminated quote produces a localized `VOID_SCAN` (already emitted) and no other diagnostics outside the mutated line ±1.

Repro fixture: [`testdata/cascades/unterminated-quote/minimal.decl`](../../testdata/cascades/unterminated-quote/minimal.decl). The M12.2 locality harness fails on this fixture today; landing M12.3 makes it pass.

## Scope

- **Layer:** scanner ([`internal/scan/`](../../internal/scan/)). The cascade is upstream of the parser — the parser is consuming what the scanner hands it.
- **Recovery strategy candidates** (pick during implementation; not all need to land):
  - **Newline-terminated quotes.** Treat `\n` inside a quote-in-progress as terminating the literal (emit `VOID_SCAN unterminated quote`, end the string at the newline, resume normal scanning on the next line). Matches what most line-oriented linters do for unterminated strings. *Concern:* the corpus may contain valid multi-line quoted strings — verify before adopting.
  - **Bounded recovery.** Keep the existing "consume to next `"` or EOF" but cap recovery at K bytes / lines and emit the `VOID_SCAN` at the opening quote, then re-enter normal scanning. *Concern:* arbitrary K.
  - **Two-pass scan.** First pass detects unterminated quotes; second pass treats them as no-op (skip the content entirely for parser purposes). *Concern:* heavier change.
- **Parser-side support:** none needed if recovery is purely scanner-layer. Verify by running the M12.2 harness pre/post fix — the cascade should drop from N to 0 outside diagnostics, with the existing `VOID_SCAN` diagnostic preserved.
- **Tests:** the existing co-located scanner tests pin byte-level scanner output. The fix will change the scanner's output on unterminated-quote inputs — update the corresponding `*_test.go` expectations (one or two assertions in [`internal/scan/scan_test.go`](../../internal/scan/scan_test.go) and any downstream parse/validate tests that consume the new token stream).
