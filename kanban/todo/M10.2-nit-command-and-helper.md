# M10.2 · `/nit` command + file-a-nit helper

**Status:** todo
**Goal:** M10
**Size:** medium

## What
Build the user-facing capture mechanism. `/nit "<description>"` prompts for `Paths:` (and optionally context), then commits a markdown file to the `nits` branch via the sibling worktree. Capture never touches the user's active branch.

## Scope
- New `.claude/commands/nit.md`:
  - Accepts `$ARGUMENTS` as the nit description.
  - Prompts the user once for `Paths:` ("Best guess at the file or glob this touches?"). Required — refuses to file if the user can't name one.
  - Optional follow-up prompt for one paragraph of context.
  - Calls `tools/nit.sh` with the gathered fields. Reports the committed file path on success.
- New `tools/nit.sh`:
  - Args: `--description <str> --paths <glob> [--context <str>]`.
  - Verifies `../void-slice-nits/` worktree exists; if not, errors `run tools/nits-bootstrap.sh first` and exits non-zero.
  - In the nits worktree: `git fetch origin nits && git reset --hard origin/nits` (sync before write).
  - Writes file at `kanban/nits/<timestamp>-<slug>.md`.
    - Timestamp: `YYYYMMDDTHHMMSSZ` (UTC, no separators — sortable, filename-safe).
    - Slug: lowercase, alphanumerics and hyphens only, derived from description, truncated to 40 chars.
  - File format (literal, copyable):
    ```markdown
    # <description>

    **Captured:** 2026-05-05T14:30:22Z
    **Branch:** <originating-branch>
    **Paths:**
    - <glob>

    <optional context paragraph, omitted if not provided>
    ```
  - `git add`, `git commit -m "nit: <description>"`, `git push origin nits` with retry: 2s, 4s, 8s, 16s exponential backoff (per CLAUDE.md § Git Operations).
  - On final push failure: print `captured locally on nits branch but not pushed; run 'git -C ../void-slice-nits push origin nits' when network returns` and exit non-zero.

## Dependencies
M10.1.

## Verification
- `/nit "test capture"` from an arbitrary branch produces a file on `origin/nits` at `kanban/nits/<timestamp>-test-capture.md`.
- The file has all four required fields (description heading, `Captured:`, `Branch:`, `Paths:`).
- The active branch's working tree and HEAD are unchanged after `/nit` runs (verify via `git status --porcelain` empty and `git rev-parse HEAD` matches pre-invocation).
- Running `tools/nit.sh` without `tools/nits-bootstrap.sh` having been run errors out clearly and exits non-zero.

## Out of scope (intentionally deferred)
- Multi-Paths nits — single glob only at v1. Multi-glob support adds adoption complexity (subset check across N paths) without clear demand yet.
- Editing or deleting nits via `/nit` — capture-only command. Manual `git rm` in the worktree is the deletion path.
- Auto-Paths inference from `git diff` or open files — fragile, surfaces the wrong default more often than not. Explicit prompt is cheap and correct.
- `/nit` listing pending nits — listing happens during `/goal-define` (M10.3) and `/goal-slice` (M10.4), not `/nit`.
