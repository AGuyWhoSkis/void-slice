# M12.7 · Recover locality when a mid-file `}` is missing (greedy-match cascade)

**Status:** in-progress
**Goal:** M12
**Size:** medium
**Origin:** M12.5

## What

Greedy brace-matching makes the parser silent until EOF when a `}` is missing
in the middle of a deeply-nested file. M12.5 anchors diagnostics at EOF *when
the parser detects EOF inside an unclosed object value*, but for the case
below no inner `expectSym('}')` ever fails — each greedily grabs the *next*
available `}`, shifting every downstream close up one nesting level. The
fault only surfaces at the outermost top-level `expectSym('}')`, lines below
the actual mistake.

Discovered on the preview deployment with this sample:

```
Version 1                                            <- 1
component {                                          <- 2
	cpntTest myTest {                                <- 3
		edit = {                                     <- 4
			m_items = {                              <- 5
				num = 2;                             <- 6
				item[0] = { m_val = "a"; }           <- 7
				item[0] = { m_val = "b"; }           <- 8
				item[1] = { m_val = "c";             <- 9  ← missing `}` here
			}                                        <- 10
		}                                            <- 11
	}                                                <- 12
}                                                    <- 13
```

Today: `PARSE_EXPECTED_SYMBOL expected '}' to close component block` at
line 14 col 1 (EOF). Each `}` on lines 10–13 closes one level *inner* than
intended — the file lints to a structurally-mismatched parse with the error
reported as far away as possible from the cause.

After the fix: diagnostic anchored within ±1 line of line 9 (where the brace
is missing), naming the object that's actually unclosed (`item[1]`'s value).

## Scope

### First: a failing test that replicates the gap

Land this **before** any fix code. The test is the regression contract for
the work that follows.

1. Commit the sample as a new fixture
   `testdata/cascades/missing-mid-file-brace/minimal.decl` (verbatim above —
   13 lines, trailing newline).
2. Add a test in `internal/harness/locality/locality_test.go` (extend

   must fail on `main` with the current EOF-anchored cascade
   (`PARSE_EXPECTED_SYMBOL` at line 14) and become the green gate for the
   fix.

### Then: the fix

- **Layer:** parser ([`internal/parse/parse.go`](../../internal/parse/parse.go)).
- **Two candidate approaches** (pick during implementation; trade-off is
  brittleness vs. coverage):
  - **Indent-aware close.** Before consuming a `}` in `expectSym('}')`,
    compare the `}`'s column to the matching `{`'s column. If the `}` is
    at strictly *less* indentation than the `{`, treat it as belonging to
    an outer scope — emit `PARSE_UNTERMINATED_OBJECT` anchored at the inner
    `{` and let the outer level consume the `}`. Catches the sample (line 10's
    `}` is at column 4 vs `{` at column 17). *Concern:* files with
    inconsistent indentation get false positives; treat indent as a soft
    *signal*, not a hard rule (e.g. fire only when the column delta is ≥
    one tab).
  - **Pre-scan brace+indent stack.** Walk the token stream once before
    `WalkEntities`, push `{` and pop `}` while tracking indent. Where the
    pop's indent disagrees with the push's, flag a depth-mismatch anchor.
    Heavier; works even without `expectSym` failing. *Concern:* duplicates
    work the parser already does.
- The fix must keep the existing M12.3/4/5 fixtures passing — the
  unterminated-brace minimal fixture already exercises the EOF-detection
  path and shouldn't regress.

## Out of scope

  M12.7 fixes the locality of the first/deepest mismatch.
- Indentation-as-grammar — this fix uses indentation as an error-recovery
  signal only; the grammar stays brace-based.
- The other M12 follow-up (M12.6) on EOF-anchor refinement for trailing-`\n`
  files — orthogonal.
