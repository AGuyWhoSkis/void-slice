# M17.3 · Top-level cascade gate at `walkEntities` entry

**Status:** in-progress
**Goal:** M17
**Size:** small
**Origin:** [M17-root-causes.md §3 ticket 1](../goals/M17-root-causes.md)

## What

[`internal/parse/parse.go:453-489`](../../internal/parse/parse.go#L453-L489)'s top-level `for !c.eof()` loop has no abort condition: every IDENTIFIER that isn't `component` emits `UNEXPECTED_TOKEN` "expected 'component'" and every non-IDENTIFIER emits `UNEXPECTED_TOKEN` "unexpected token at top level", then `c.next()` advances and the loop continues. When the first significant token isn't `{`, `Version`, or `component`, the parser runs the entire remaining token stream through this loop — one diagnostic per token. M17.1's punctuation probe found this produces up to **223,305** `PARSE_UNEXPECTED_TOKEN`s on a 1.78 MB animset when its file-root `{` is flipped to `(` (SC-1), and 8 diagnostics on the 38-byte [`testdata/golden/eof.line-comment-no-newline.decl`](../../testdata/golden/eof.line-comment-no-newline.decl) when its `// ` prefix is stripped (SC-3). Both cascades route through the same site; one gate closes both.

Add a structural gate at [parse.go:430](../../internal/parse/parse.go#L430)'s decision point: after skipping leading comments, if the first significant token is *neither* `{` *nor* the `Version` identifier *nor* the `component` identifier, emit exactly one `PARSE_EXPECTED_SYMBOL` at that token's span with message `expected '{' at top level` and return without entering the for-loop. M12.16/M12.17 are the direct precedents — both gated a cascade at an entry point with no abort condition.

## Scope

- **Edit [`internal/parse/parse.go`](../../internal/parse/parse.go) `walkEntities`.** Insert the gate between the curly-shape check at [parse.go:430-441](../../internal/parse/parse.go#L430-L441) and the `Version` match at [parse.go:444](../../internal/parse/parse.go#L444). The order is: skip leading comments (existing); if `{` shape, recurse and return (existing); peek next significant token — if it's *not* `Version` and *not* `component`, emit one `PARSE_EXPECTED_SYMBOL` at the token's span ("expected '{' at top level") and return. Only when the token *is* `Version` or `component` do we fall through into the existing `Version` match and for-loop.

- **Diagnostic shape.** Code: `Codes.EXPECTED_SYMBOL` (matches the existing convention at [parse.go:434](../../internal/parse/parse.go#L434)/[parse.go:495](../../internal/parse/parse.go#L495)/[parse.go:505](../../internal/parse/parse.go#L505)). Span: the offending first-significant-token's `Span` (not offset 0 — the user wants a caret at the byte that's wrong). Message: literal string `expected '{' at top level`.

- **Add a regression test in [`internal/parse/parse_test.go`](../../internal/parse/parse_test.go).** Three sub-cases:
  - `TestM17_3_RootBraceFlipEmitsOneDiag` — input `( a b c d e f g h i j }`. Assert exactly one diagnostic, code `PARSE_EXPECTED_SYMBOL`, anchored at the `(`.
  - `TestM17_3_BareIdentifiersDoNotCascade` — input `normal line comment, no newline at EOF` (the SC-3 fixture's post-strip content). Assert exactly one diagnostic, code `PARSE_EXPECTED_SYMBOL`, anchored at `normal`.
  - `TestM17_3_VersionAndComponentStillPass` — inputs `Version 1\ncomponent Foo Bar {}` and `component Foo Bar {}`. Assert zero `PARSE_EXPECTED_SYMBOL` from the new gate (both shapes were legitimate before and must remain so).

- **Re-run M17.1's punctuation probe and pin the collapse.** From repo root: `go run ./testdata/m17-probes/run -family=punctuation`. Compare the new findings file against [`testdata/m17-probes/findings/punctuation.txt`](../../testdata/m17-probes/findings/punctuation.txt). The 41 `note=brace-to-paren, offset=0` rows that previously showed `+PARSE_UNEXPECTED_TOKEN×N` (N up to 223,305) must now show `+PARSE_EXPECTED_SYMBOL×1` (and no `PARSE_UNEXPECTED_TOKEN` term). Commit the updated findings file as part of this ticket — it's the lasting evidence the fix landed.
